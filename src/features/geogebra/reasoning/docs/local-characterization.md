# 黑盒对象的局部条件建议与多构型检查

2026-10-19。P2 首批实现。入口是 Conditional reasoning → Suggest conditions。

## 本批交付

自动建立局部候选池，给依赖点挑选少量刻画条件；默认在独立 GGB 副本里检查
六个变化构型。结果先作为建议展示，由用户一次接受，再指定目标。现有人工选择
继续可用。整个建议算法不接收目标，不从目标证明失败中反向添加前提。

角候选现采用独立发现的直线有向角（模 π）；无向角保持人工候选语义，
不参与默认局部建议。定义与跨分支验证标准见 [角语义规范](angle-semantics.md)。

依赖关系可以来自不理解语义的表达式。部分 AST 解析只降低作用域的确定性，
不会直接禁止黑盒对象；循环、缺失父节点和读取失败则停止该对象的建议。
列表内对象引用已修正：`{C}` 的大括号是列表边界，不再吞掉对 C 的依赖。

## 独立候选池与归属

1. 按完整依赖图稳定拓扑排序，保留输入顺序处理可交换节点。
2. 每个依赖点先选自身及较近的祖先点，非点对象仍参与依赖路径。
3. 对这个局部点集独立运行现有关系发现，关闭生成模型和后果压缩，不使用
   主面板的显示过滤、价值分阈值或保留列表作为候选输入。
4. 将分组观测拆为独立语义条件，只保留涉及该输出点的条件。有限族按实际
   实例处理；老对象间的关系不会顺带成为新对象的前提。
5. 若祖先范围的局部秩仍不足，再按选项搜索较早且共享祖先的对象，额外增加
   条件成本，并在对象报告中列出这些上下文。不会使用拓扑顺序中较晚的对象。

拓扑可交换节点的顺序不是对真实用户操作历史的恢复。多输出构造的联合刻画
仍需以后增加构造步骤分组；当前循环输出会被标记不可用。

默认最多处理 16 个依赖点，每个作用域 10 点、80 条原子候选，总共建议
24 个条件。局部发现每次有 3000 个三角形／角和 40000 次比较预算。
候选预算仍可能漏检，结果不宣称穷尽。搜索在独立 Worker 内，30 秒停止。

## 几何约束能力

在固定已有点的坐标后，将候选写成输出点 X 的数值残差 r(X)，包括共线、
垂直、等长、中点、共圆、有向角和长度方程。坐标先归一化，用中心差分
估计 Jacobian，比较两个方向的独立性及条件数。步长为 1e-5；归一化残差
阈值为 2e-6；秩判定的特征值比阈值为 1e-5。退化和不稳定条件不会贡献秩。
有向角残差按模 π 计算，中心差分使用局部提升增量；不将代表值的切口当作不连续。

贪心选择“新增局部秩／表达成本”较大的条件；中点的两个残差可由一个语义
条件提供。相同／近乎平行的约束不会因换了写法反复贡献秩。成本考虑谓词、
参与点数、系数和是否使用较早上下文，不使用原命令名称或 novelty 分数。

秩 2 仅报告当前点在固定背景下局部受限；不表示全局唯一、原始定义已恢复、
条件普遍有效或推理器一定能推出其他性质。秩 1 可能是合法的一维轨迹，
不会为了凑足两式而强行接受远端性质。秩也不是代数表达式空间的行秩。

## GGB 副本和分开的验证构型

主引擎只执行读取 API 和 exportGgb。副本在独立 iframe 及 API 句柄内打开，
关闭材料 JavaScript、文件加载随机化和自动动画。开始先核对副本能否复现
原快照，失败时明确报告，不修改主构图、不放宽见证容差。

只改变 API 确认 independent 且 movable 的二维自由点；路径点、标量、滑块、
固定点均不主动扰动。六次变化以原输入为基准，混合 0.12、0.35、0.7、0.2、
0.5、0.85 倍输入尺度的独立坐标位移，固定 seed=294731。至少三个自由点时
一般会改变形状；少于三个时明确提示形变覆盖有限，不能把它当成充分的独立检验。

前四个构型用于筛除候选，后两个构型留作验证。要求至少三个已定义的前置
构型、至少一个已定义的验证构型通过；记录有效／跳过数及完整坐标样本。
候选在前四个里出现反例会被剔除，最多保留每对象八条反例摘要及其构型号。
已经选出的描述若在验证构型失败，会删除失败条件并报告不足，**不会再用
这两个构型拟合替代条件**。这让“未通过验证”成为可见结果，而非悄悄重选。

副本采样最多 160 个有限点、24 个可移动自由点，45 秒停止。取消、构图更新
和离开页面会移除 iframe 及事件监听器；分析 Worker 也同时失效。只改变这些
输入得到的有限次数值结果依然不是证明，滑块及其他自由参数仍可能隐藏反例。
依赖脚本或随机行为的材料可能无法复现，应使用人工条件或明确的临时建议。

## 条件性推理覆盖

Evaluate coverage 使用建议集作为唯一前提，查询剩余局部候选以及当前主列表
中可用的其他观测。至多 64 组查询，共用一次 DDAR 闭包和同一个名称／坐标
映射。查询不会进入 force_pred，受 40 点／250 谓词预算限制的项目单独计数。
界面展示推出比例与未覆盖条件列表；未推出不代表性质错误。此操作不改变建议或
接受集，不为了提高覆盖率自动承认更多性质。

Accept suggested conditions 会替换接受集并清空目标；之后再选择目标。单独
接受或撤销其他条件仍可用。新增建议池时，原有同快照且语义未变的人工条件
保留；构图变化后全部失效。项目 JSON 包含完整建议、秩、选择成本、样本、
反例和覆盖报告。没有独立证明证书。

## 验证与后续

回归覆盖黑盒中点、未知函数名的 O/H/I、合法一维点、重复／近相关约束、
循环依赖、特殊位置反例、留出验证失败后不重拟合，以及实际自动条件到
原生 AG2 的推理。原生多查询回归同时查询一个真后果与一个错误目标，
确认后者没有因为进入查询批次而被当成前提。

仍待推进：独立副本的更多自由参数、全局分支／充分性分析、根据推理覆盖
搜索补充引理、反向删除冗余建议、联合刻画多输出构造、局部增量缓存和
证明来源／证书。当前实现只在有预算的语言与样本内寻找较好的局部描述。
