# 自动关系发现：价值评分改进设计

状态：分析与提案，尚未实现。分析日期：2026-10-18；基于提交 `8d95e8a`。本轮只新增文档，不修改算法、类型或指令执行逻辑。现状入口见 [README](../README.md)。

## 1. 先确定“价值”的含义

建议目标是：**相对于用户实际采用的作图方式及已经明确的知识，这条成立的关系提供了多少额外信息。**

同一组坐标、同一数学结论，不必有相同分数。直接调用 `Q=IsogonalConjugate(A,B,C,P)` 已经把等角共轭关系告诉了系统；通过反射点的外心获得 Q，则还需要识别一个几何事实。这种差异应当保留，但它只是“稍微更不平凡”，不能因为多了几个中间对象就获得不成比例的奖励。

同时，应分开记录以下概念：

| 概念 | 回答的问题 | 建议表示 |
| --- | --- | --- |
| 成立证据 | 当前近似成立、拖动后保持，还是已有证明？ | 数值残差、条件质量、验证状态／证明来源 |
| 定义可知性 | 是否是指令直接承诺的结论或很短的推论？ | 匹配到的定义事实、推导规则及代价 |
| 作图非平凡程度 | 是否连接了原本不同的作图分支？ | 局部结构特征，含来源可靠性 |
| 展示增益 | 是否重复已显示结论？ | 关系覆盖与冗余信息 |

本轮后续实现应先改善后三项中的评分基础，复用现有四种检测器。多构型验证和更多关系检测器可后续独立补充，不应成为首轮交付的前置条件。

## 2. 当前算法值得保留的部分

1. **点对与方向族复用。** 不要求用户先画线；共线、平行和垂直可以共享基础几何结构，按族输出能减少大量重复条目。
2. **数值保护已有基础。** 平移／尺度归一化、极端点隔离、近共线三元组拒绝，以及候选聚类后的点位复核，比直接对原始坐标比较更稳健。
3. **别名展开晚于几何发现。** 重合点不会仅凭名称数量制造三点共线或四点共圆；新增别名也不直接按人数增加分数。
4. **图层与检测层已有一定分离。** 完整图包含非点对象，未来能提供作图语义的载体；界面筛选不会直接篡改分析图。
5. **现评分简单、解释明确。** 深度、祖先和跨分支可以继续作为弱特征，无须完全抛弃依赖图。

## 3. 发现算法的限制及其对评分的影响

### 3.1 当前数值成立不等于几何恒真

一次坐标快照无法判断自由点是否恰好排成一线、直角或共圆。遍历的候选越多，偶然近似成立的机会也越多。现有 `confidence` 并非按这些因素计算：自由点的巧合可能同时具有高依赖分离分和高百分数。

建议检测器逐步提供归一化残差、退化／病态指标和验证状态。单个构型的证据先标为 `numeric-only`；不能仅因点数增加，就声称具有更高概率的真实性。首轮至少调整解释和状态设计，避免把“有意思”与“可信”混为一个数字。

后续多构型验证应尊重真实自由度、点在路径上的约束和分支选择，优先用隔离副本或独立评估器。读取用户拖动后的结果可积累被动证据，但不能把多个无有效自由度变化的快照当成独立检验。证明另设状态。

### 3.2 聚类是有损搜索

- 方向并查集有传递漂移；当前稳定性检查会放弃部分方向族，可能牺牲召回率。
- 共线簇的锚点检查没有为整个簇给出统一的最佳拟合与残差输出；不应将容差簇当成精确等价类。
- 圆心／半径在近共线三元组下病态；即使径向接近，某些近直线构型仍值得降级。
- 圆簇若因传递连接而整体复核失败，当前是丢弃整簇，未拆分出其中有效子簇。
- 三点圆按对象枚举顺序取前 8000 个有效候选，桶代表也只取前八个；添加对象或重排名称／顺序可能改变召回。

建议先保留检测器，把这些作为检测证据和预算诊断输出。随后再做确定性候选采样、圆的支持点扫描、失败簇拆分与局部重拟合；不要依赖评分修复漏检。

### 3.3 关系族与最小命题混在一起

一个平行族可能包含许多已由定义给出的平行线，也可能只有一条跨分支线值得关注。把全族点名压成一个无角色集合，会把真正新颖的局部结论稀释；反之，堆积辅助点也可能改变分数。

建议内部区分“最小关系命题”和“供 UI 汇总的关系组”。共线用三点或点在线上，共圆用四点或点在已确定圆上，平行／垂直用两个有端点角色的支撑直线。组内保留有价值的少量见证，避免穷举所有等价子集。

## 4. 当前评分的主要失真

### 4.1 祖先相似度不是依赖紧密度

当前祖先集合不含点自身。若 A、B 为自由点，M 依赖 A、B，则：

```text
Anc(A) = ∅
Anc(B) = ∅
Anc(M) = {A,B}
```

三对祖先交集全为空，因此 `branchDiversity=1`。虽然有两对直接依赖，独立性项只占 20%，而分支项占 55%。于是“中点与端点共线”仍被赋予高分。

将祖先改成包含自身可修正这个局部反例，但远不足以解决问题：长链会稀释祖先权重，高元关系中的大量自由输入点对仍会稀释输出与输入的紧密关系，也仍然不能辨认关系语义。

### 4.2 所有输入互不为祖先，掩盖一次多输入构造

`A,B,C,P → Q` 是一个整体构造。五个点共有十对，只有 Q 与四个输入的四对存在祖先关系，其余六对互相独立，因此 `independenceFactor=0.6`。

输入越多，这个比例问题越明显。将构造的所有参数摊平成两两比较，无法表达“这个输出正是由这一整组输入直接定义”的紧密联系。需要显式记录操作及参数角色，按超边／构造操作匹配关系，而不是仅修改点对平均的系数。

### 4.3 原始深度奖励了表示长度

当前平均深度不区分有意义的几何步骤、复制赋值、命名包装与复杂匿名表达式。把步骤展开成命名对象会增加图深度；同样复杂的匿名表达式仍可能只有一层直接依赖。

深度可以是辅助证据，但不能等同于数学难度，也不宜作为恒定正奖励。用户明确展开步骤可以影响非平凡程度；没有语义增量的中转和对象数量不应影响它。

### 4.4 共同背景可能压低真正有价值的结论

三角形中的不同中心经常共享 A、B、C。共同祖先多，可以代表相同研究背景，并不必然代表相关结论显然成立。例如某个中心共线结论不能仅因各中心都依赖 ABC 就被强罚。

反过来，直接调用 `EulerLine` 或以一个中心对另一个中心作线性组合得到第三点时，相应结论可能就是定义或短推论。结构相同或相近的图，应允许关系语义带来不同分数。

### 4.5 缺失信息被当成独立性

读取失败会被接到根；根不进祖先集合，因此未知依赖可能表现为完全独立。解析 `partial/failed`、非几何参数、`fallback` 的可信度目前未进入评分。强连通分量内部成员不互列为祖先，甚至可能被统计为独立点对。

建议未知状态单独记录，不能作为“发现了独立分支”的正证据。SCC 可以继续用于稳定计算，但内部关系应标为互相关联或异常，不奖励独立性。

### 4.6 截断、别名与 ID 会造成额外偏差

共线／共圆只用最多八个见证代表评分，平行／垂直却使用全部代表。超过八个点时，显示的完整结论与实际评分对象不一致。显示见证上限不应成为评分上限。

重合点先选代表、再评分，可以避免重复名称刷分，但代表若有不同作图来源，换输入顺序仍可能换分。几何重合应保留每个对象的来源，不可直接宣告它们定义等价。今后若发现“两个独立构造的点重合”，这本身就是值得评分的命题。

部分 ID 含方向并查集索引或依赖枚举顺序的名字串，也不适合作为长期稳定的语义标识。今后应使用关系种类、角色和经过对称性规范化的对象身份；几何位置聚类与对象身份分开管理。

## 5. 用现函数复核的反例

以下直接调用当前 `buildDependencyGraph`、`buildDependencyProfile`、`measureDependencySeparation` 和 `scoreDependencySeparation`，仅构造内存输入，不修改仓库代码或测试。分数取两位小数：

| 依赖情形及被评分点集 | B | 平均深度 | I | 分数 |
| --- | --- | --- | --- | --- |
| 三个自由点 A、B、C | 1 | 1 | 1 | 82.09 |
| 自由 A、B；`M=Midpoint(A,B)`；评分 A、B、M | 1 | 1.3333 | 0.3333 | 70.64 |
| 自由 A、B、C、P；`Q=IsogonalConjugate(A,B,C,P)`；评分五点 | 1 | 1.2 | 0.6 | 75.24 |
| 同样四个自由输入；三个反射点，再取其外心 Q；仍评分五点 | 1 | 1.4 | 0.6 | 76.32 |
| 人工循环输入 `A←B←A`；评分 A、B | 1 | 1 | 1 | 82.09 |

前两行的分数与具体关系种类无关；只有数值检测恰好发现关系时才会显示。等角共轭两行是对指定点集的评分探针，**当前检测器没有等角共轭关系类型**，不会直接生成该结论。循环行是容错边界探针，不表示正常引擎允许这样的构造。

黑盒与展开作图仅差约 1.08 分，且差值完全来自深度项。把现有三个权重重新调一遍，不能补回所缺失的“这是什么构造、它直接说明了什么”信息。

## 6. 建议的数据基础：保留用户操作边界

### 6.1 两种视角共同保留

建议保留当前完整对象图，另外记录语义作图操作：

```text
ConstructionOperation（概念设计，非现有类型）
  id / definitionRevision
  origin: native | site-tool | file-tool | manual-expression | unknown
  resolvedToolIdentity / overload / toolVersionOrDefinitionHash
  originalExpression / evaluatedExpression
  inputs: 有角色与次序的对象或子表达式引用
  outputs: 对象身份、输出槽位与有效条件
  authoredBoundary: 用户直接调用 / 用户明确展开 / 编译器内部展开
  semanticFacts: 可由该操作可靠承诺的关系
  sourceQuality: 完整记录 / 可靠重建 / 部分解析 / 未知
```

对象图回答“数值上依赖谁”；操作记录回答“用户用哪一个概念直接造出它”。多输入／多输出用一个操作节点连接，不能拆成互不相关的若干点对。内部实现可保留供审计，但默认不按其算术表达式长度增加用户作图深度。

### 6.2 当前 custom 编译链的关键缺口

[`commandPipeline.ts`](../../commands/commandPipeline.ts) 已在 `CommandResult` 中保留原始 `command`、`expandedCommand` 和结果 `labels`；但它们没有形成分析模块可查询的逐对象来源。

[`commandCompiler.ts`](../../commands/custom/commandCompiler.ts) 把站点工具展开为原生表达式，点等角共轭的 [`conjugate` builder](../../commands/custom/builders/index.ts) 用重心／齐次表达式和匿名绑定实现几何。`getCommandString` 未必还能恢复用户所写的 `IsogonalConjugate`。因此只在分析模块对最终指令文本匹配工具名是不完整的。

建议未来在**解析分派完成、实际执行成功并绑定输出后**记录工具身份与参数。不得凭命令文字就登记成功构造；多行指令可能部分成功，多输出也需逐槽绑定。嵌套调用保留语义子表达式，无需真的创建中间几何对象。

文件工具／文件内 callable 在调用点可覆盖站点命令，别名也可能被覆盖。语义标签必须使用实际解析到的实现及重载；不能看到字符串 `IsogonalConjugate` 就假定它拥有站点工具的数学含义。任意未知自定义工具，可以认为输入输出在同一次操作中很紧密，但不能未经声明就声称某个具体几何事实由其定义保证。

### 6.3 旧文件、导入与生命周期

来源恢复顺序建议为：有效操作记录 → 可识别的原生定义／文件工具契约 → 有限表达式模式识别 → 纯结构降级。不要对复杂匿名公式做全面的数学反编译。

当前 `GeometryProjectRecord` 没有此类来源字段，命令历史也只是组件内最多 100 条文本。未来若需刷新／导入导出后保持分数，应单独设计带版本的来源保存；浏览器草稿附带元数据可先做，普通 `.ggb` 若不携带这些信息就必须标明降级，不能承诺无损恢复。

来源记录需跟随改名、删除、重定义、撤销／重做和工具变更维护。用对象身份与定义修订校验绑定，避免同名新对象继承旧标签；不以坐标变化本身判定定义失效。不能只依靠“一次执行返回的标签”永久绑定。

## 7. 评分流程建议

### 7.1 建立带角色的关系事实

例子：

```text
Collinear(A,B,M)
Parallel(LineThrough(A,B), LineThrough(C,D))
Perpendicular(LineThrough(A,H), LineThrough(B,C))
Concyclic(A,B,C,D)
IsogonalPair(referenceTriangle=(A,B,C), pair=(P,Q))   // 未来类型
```

按数学对称性规范化：线的两端可交换，平行线可交换；等角共轭的三角形角色与输入输出要明确。角色不同的关系不能只用相同点名集合共用一个分数。

用惰性的线／圆表达式表达未命名对象，不要求为所有匿名对象真正增加 GeoGebra 顶点。

### 7.2 先识别“作图已知”，再看结构

为可靠构造注册精简的语义契约。契约是可匹配的事实模板和前提，不是工具名或自然语言描述：

| 构造 | 可登记的定义事实／短推论 |
| --- | --- |
| `M=Midpoint(A,B)` | 非退化时 A、M、B 共线，且 AM=MB。 |
| 过 P 作已知直线的垂线 | 新线过 P，且与原线垂直。 |
| `X=Intersect(l,m)` | 在输出有定义且满足分支条件时，X 在 l 与 m 上。 |
| `X=Point(c)`，c 为圆 | X 在 c 上；同一已知圆上四点共圆属于很短推论。 |
| 可信站点点重载 `Q=IsogonalConjugate(A,B,C,P)` | 在定义域内，P、Q 关于 ABC 等角共轭。 |
| 三个指定反射点再取外心 | 登记反射和等距事实；到等角共轭需额外的识别规则。 |

规则均需检查对象类型、非退化条件和实际工具身份。例如四点／直线重载、圆退化以及未知文件宏不得共享同一个无条件契约。

推荐采用有预算的局部事实匹配／推导：

1. 只以可靠作图定义事实和允许的规则为前提。
2. 命中目标即返回最短已找到的说明和代价。
3. 直接定义最便宜；初等闭包次之；识别一个熟知构造定理再高一点。
4. 搜索达到预算仍未命中，结果是“未找到短说明”，不能当成“证明很难”。

不要把本次所有数值候选直接加入事实库，互相证明后一起降成平凡。若后续做候选间蕴含／展示去重，必须与定义可知性分开，且避免循环支撑。

### 7.3 结构特征改为局部、带角色的辅助证据

- **直接操作覆盖：** 一个操作是否同时覆盖目标关系的关键输出与必要输入？这应比自由输入两两独立更有影响。匹配的契约可强降分；单纯共享操作只能作紧密性证据。
- **近距离依赖：** 使用包含端点的局部路径和距离衰减；直接依赖强、远祖先弱。哨兵根不得作为所有自由点互联的捷径。无路径且来源未知应标为未知，不记作最大距离。
- **分支桥接：** 关系是否连接了不同构造输出分支？可共享 ABC 等背景，将其影响下调，但保留对输出的直接操作匹配。普通共享父节点不能一律删除。
- **有效步骤：** 折叠赋值、可确认的恒等包装和编译器内部展开，保留用户明确构造的几何步骤。仅 UI 隐藏／显示不改变分数。
- **多输出关联：** 同一个工具的多个输出彼此也紧密，不能因为没有输出间的有向边就判为独立。

局部路径或近邻摘要应缓存，避免为每个候选重复遍历整张图。可先使用关系各角色之间的少量最短路径及操作覆盖，不必一开始实现昂贵的最小连接子图优化。

### 7.4 一个可校准的合成方式

建议先保存评分分解，之后再确定总分。以下仅为实现起点，不是已经确定的权重或概率模型：

```text
T ∈ [0,1]：由可信定义和短推论说明目标的程度
H ∈ [0,1]：排除无意义包装后的有效推导跨度
B ∈ [0,1]：带角色、扣除普通背景后的分支桥接程度
C ∈ [0,1]：相对定义已知事实的额外独立约束（首版可用简单模板近似）

V_base = 100 × (1-T) × (0.55 H + 0.30 B + 0.15 C)
```

- 直接定义命中：`T=1`，该定义关系价值为 0 或落入 UI 的最低档；不能被深度／人数重新抬高。
- 很短推论：T 较高；熟知构造的另一种描述：T 稍低，因此展开作法可适度提高分数。
- 没有契约命中：T 未获正证据；H 不能因搜索超时就取 1，应按结构回退并标记不确定性，必要时只给价值档位／区间。
- 来源部分缺失：不把缺失当桥接，不拿低来源质量乘 T 后反向抬高分数；改用降级模型和独立的来源状态。
- 成立证据不足：放入数值候选层，不能仅凭高价值排到已可靠验证的结论之前。首版若全是单构型结果，可在同层比较价值。

这里的 C 应表示约束是否已由定义提供，不按点数线性累加，也不要求首版做完整代数独立性检验。若这项暂时无法稳定实现，可以先省略并重新归一化权重。

实际优先级应先满足成对偏好与解释，再拟合标量权重。可以先交付“直接给出／短推论／潜在新关系／来源未知”分层，再在层内用结构分，减少伪精确。

### 7.5 去重与关系组计分

先给最小命题评分，再组装关系族。组的主分可取其最高价值的可靠见证，并显示该见证；新增非冗余覆盖只作小幅、封顶的补充或次级排序。其他见证可展开查看，不能因一条高分见证就暗示组内每个子结论都同样新颖。

已被定义保证的线族若增加一个来自独立分支的新点，应突出“该点也在这条线／这个圆上”；已有点群不应稀释它。相同共线集合中的大量三点命题、同一方向族的许多线对，不累加刷分。显示最多八个见证与评分的数据范围应完全解耦。

## 8. 等角共轭案例的预期行为

以下以非退化三角形、各输出有定义为前提。反射点的外心与等角共轭的识别规则应有适用条件，不把退化状态强行套入。

| 作图方式 | 系统可知信息 | 对“P、Q 等角共轭”的预期 |
| --- | --- | --- |
| 直接调用可信 `IsogonalConjugate` | 用户直接请求此关系，内部可能是重心公式 | 最低档；依赖在语义上很紧密，内部计算长度不加分。 |
| 用户明确作 Pa、Pb、Pc 三个反射点，再取外心 Q | 直接知道反射与等距，还需识别一个构造事实 | 比直接调用稍高，仍属于熟知构造的短说明。 |
| 同样的工具在编译器内部展开出复杂匿名表达式 | 用户仍只调用一次有明确语义的工具 | 与直接调用接近；不能把编译器展开当作用户多步作图。 |
| 上述命名中间对象只被切换可见性 | 定义和用户操作边界没变 | 不因显示／隐藏切换而变分。 |
| 不同且没有明显对应定义的作法得到 Q | 未命中短说明，结构提供部分线索 | 可以更高，但不能据此宣称定理更难或恒真。 |
| 导入文件，只剩复杂原生公式，来源不可恢复 | 有依赖但语义未知 | 标记降级；不能武断称其新颖，也不能冒认原始指令。 |

紧密性也必须针对关系：即使 Q 直接等角共轭构造而得，**Q 与另一个独立构造点之间的新共线、共圆等关系仍可能有价值**。不得把工具输出及其输入组成的所有关系一律打成零分。

## 9. 分阶段落地顺序

### A. 先用现有关系类型改进评分

1. 建立排序基准和人工偏好对，保留旧分数作比较；将数值证据与价值、来源状态分开。
2. 将评分接口从纯 `pointNames` 改为带种类／角色的命题及作图上下文；见证截断只用于 UI。
3. 为已有四种关系接入少量高覆盖契约：中点、交点、点在线／圆上、平行线和垂线；保留没有契约时的结构回退。
4. 补上站点指令实际分派及成功输出的来源记录；先覆盖现有能影响四种关系的工具，设计好保存和失效规则。
5. 使用操作覆盖与局部路径替代原始全点对平均，删除原始深度正奖励，加入未知／循环降级。
6. 关系组按关键见证计分，补充可读解释，例如“中点定义已给出共线”“在共同三角形背景下连接两个独立输出分支”。

如需更小的第一批提交，可先做第 1–3 步和未知依赖处理；但必须明确：没有第 4 步时，复杂站点工具在导入与重载情况下的语义恢复仍不完整。仅修祖先集合不能算完成整个方案。

### B. 在评分基础稳定后扩展关系类型

建立轻量的关系类型注册边界：每种类型提供候选生成、数值判定／退化条件、角色与对称规范化、最小见证、定义契约匹配和格式化。公共层负责来源、评分、预算、去重和解释，不要求一开始做大型插件系统。

优先可考虑等长／中点、点在线／圆上与点重合，再扩展角关系、等角共轭等有参照三角形的关系。类型具有更多参数并不意味着应得更高分；应根据候选规模和契约覆盖单独设计枚举策略。真正实现等角共轭检测时，再添加相应的构造识别规则和定义域测试。

### C. 独立改善数值证据与规模

后续增加残差及病态指标、多构型验证、稳定的候选预算和增量检测。结构未变而只是拖动时缓存依赖与契约；坐标变化只刷新数值证据。确有性能需求后再使用 Worker，避免仅通过 `setTimeout` 误以为消除了主线程计算负担。

## 10. 验收用例与校准方法

建议验证**偏好关系和不变量**，少依赖任意的精确分数断言：

| 场景 | 预期 |
| --- | --- |
| 中点定义的三点共线 vs 跨独立作图分支的共线 | 后者在同等成立证据下优先。 |
| 已显式构造垂线的垂直关系 | 降入定义／短推论档。 |
| 多点都由同一圆上的 `Point` 构造 | 共圆为已知短推论。 |
| 同一 ABC 背景下两个独立几何分支的结论 | 不因共有 ABC 就一概低分。 |
| 黑盒等角共轭 vs 反射点外心法 | 后者稍高；不按辅助点数量线性增长。 |
| 等角共轭输出参与另一个新共圆关系 | 不因输出来自熟知工具就强制降至最低。 |
| 添加别名、恒等中转、无关对象；只改可见性 | 原命题基础分稳定；候选预算影响另行诊断。 |
| 添加真正独立的几何步骤 | 可改变非平凡程度，须有相应解释。 |
| 重命名、对象次序和关系对称参数置换 | 在来源完整、预算未截断时语义与分数稳定。 |
| 超过八个共线／共圆点，新增一个有价值点 | 评分不受展示截断影响，并突出新见证。 |
| 同位置对象具有不同来源 | 别名不刷分，独立构造的重合命题不丢失。 |
| 读取失败、部分解析、循环依赖 | 不获得独立性奖励；显示来源／图质量问题。 |
| 同名文件宏覆盖站点指令、不同重载和输出槽 | 使用实际语义；未知工具不套用站点契约。 |
| 失败或部分成功的多行指令、改名、重定义、撤销、重做 | 来源只绑定已确认对象，旧定义标签不会泄漏到新定义。 |
| 导入／刷新且来源完整；以及来源缺失 | 前者可重现，后者明确降级。 |
| 自由点恰好形成矩形，拖动后关系消失 | 单构型数值候选；不能冒充已验证恒真。 |
| 大量同方向点对、近共线点、圆候选达上限 | 有耗时／预算诊断；不影响解释的真实性。 |

校准时将同一构造的直接版、展开版、带包装版作为同一组，避免把它们分散进训练／验证集后产生虚假的泛化效果。先评估偏好对满足率、前若干条的有效发现比例、分数不变量和每类误排，再决定各特征权重；同时记录漏检与误排，避免把检测不到的关系归咎于评分。

本次已运行现有两个分析测试文件，共 29 项通过。上表是未来验收设计，尚未新增或运行对应测试；也尚未进行真实 GeoGebra 引擎的交互验证。首要结论是调整评分所用的信息和关系粒度，之后再调整权重。
