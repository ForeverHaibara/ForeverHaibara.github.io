# 浮点精度与统一关系目录

2026-10-22。

## 精度修补

坐标始终来自 GGB 的原生 `getXcoord/getYcoord` 数值 API，保持 JavaScript
双精度 Number；不读取 `getValueString`，不解析显示文本，也不通过修改 GGB
的小数位设置提高精度。原读取器会将空字符串等内容转换成数字，现在只接受
有限的原生 number，其他返回值保留读取诊断，不把缺失值当作 0。

实际误匹配的主要来源是多处 `2e-7`、`4e-7`、`8e-7` 的观察容差。
现在统一在 `analysis/numericPrecision.ts` 定义，并在平移、统一缩放后的
无量纲坐标上使用：

| 用途 | 当前容差 |
| --- | --- |
| 点距、线关联、方向聚合 | 1e-11（线偏移等保留明确小倍数） |
| 有向角比较 | 2e-11 半周 |
| 普通角、长度对数、简单比例 | 4e-11 |
| 三角形形状及大小匹配 | 8e-11 |
| 独立副本基线、发现／留出样本残差 | 1.6e-10 |

这不是把浮点计算当作精确代数：仍需留出舍入误差余量。近零分母、几乎平坦
三角形的条件性、有限差分步长、Jacobian 的秩阈值分别处理；不把它们误改成
匹配容差。保留原有的近退化圆／三角形拟合保护，避免巨大圆半径吞掉有效数字。
依赖图和价值公式保持原语义。

精细区分近点后还修补了线关联：向一个支撑线组加入点时，检查新点与原组
各点间的方向。只检查相对于远端长线的横向偏移，会把两个很近的不同点和
第三点组成的狭三角形错误地当作一条线。

原回归中“近零”等测试点也调整到新容差以内。相距 1e-9 的点现在保留为
不同位置；它们若确实在同一直线上，允许报告这个真实关系，不再靠合并点
隐藏关系。新增独立反例检查近似共线、中点、共圆、等角、等长、相似／全等、
有理生成系数及细小的留出样本偏差；同时保留正常舍入误差下的真关系。

## 统一界面

侧栏只有一个 **Relations & proof** 区域、一套搜索和一个关系目录。
发现设置与自动条件建议在目录上方，依赖图默认折叠。

- 每条卡片直接显示观察、价值、采样证据，并提供 Accept condition 与
  Use as goal；展开 Details 可看谓词、对象联动、来源、生成模型与评分依据。
- All、Accepted、Goal、Rejected 是同一个目录的视图。改变查询、价值、
  显示种类或对象筛选不改变接受状态；各视图分别记住筛选，Accepted／Goal 初始显示完整选择。
- 顶部固定显示接受数量、当前目标和生成证明按钮；目标可以为空。
  证明步骤在 Proof results 区域，完成后提供 Read proof results 入口。
- 假设实验、单独检查目标及文本／项目导出折叠在 Hypotheses, checks and export；
  采样拒绝保留明确诊断，仍可显式用作假设。
- 一次先显示 100 条，可继续展开；分页不删除候选，不减少导出／证明可用的池。

`reasoning/selection/relationCatalog.ts` 按几何谓词及合取命题的规范形式合并
全局发现和局部建议。只应用谓词明确支持的对称性：普通角与有向角不同，
倍角因子不被约掉，合取命题也不与单个子命题合并。采样证据与拒绝诊断合到
同一行，旧候选 ID 保留映射供建议接受、覆盖评估与导出使用。
项目 JSON 的 `candidateAliases` 保存这些 ID 映射，可与原始局部建议对照。

同一作图快照扩展候选池时，若只是行 ID 改变，保留语义相同的选择；实际
谓词改变或作图更新则取消旧选择／证明。新目录没有隐式接受观察，也没有
把采样通过状态包装成证明。

随后修订移除了上方 Compute／Show 双列，把列表过滤放回目录，并在同快照
计算范围缩小时保留已选输入。结构化检索支持缺标点、端点换序及组内子关系；
规则和当前界面以 [结构化检索与筛选](../../reasoning/docs/catalog-search-and-filters.md) 为准。

## 检查与浏览器实测

```sh
npm test -- --run --maxWorkers=2
npx tsc --noEmit
npm run build
python scripts/geogebra-proof-smoke.py
python scripts/geogebra-pedal-smoke.py
python scripts/geogebra-reasoning-smoke.py
```

浏览器在独立 localhost 场景设置 GGB 为两位小数，P=(3,1e-8)。原生显示
API 返回 `P = (3, 0)`，坐标 API 返回 `1e-8`；关系目录仅列出两个真实中点，
没有将 P 判成 AB 中点。直接在同一目录接受 M、N 的中点条件，选择 MN∥BC，
将最低价值切为 100 后仍可在 Accepted／Goal 复核，并由真实 Pyodide Worker
生成 22 步中位线推导：5 步代数回放通过、3 项分支条件、0 个解释缺口。
独立副本在两位显示小数下完成六构型采样；同一个中点卡片显示 4+2 采样证据，
建议的旧 ID 映射后可直接接受。全仓库 43 个测试文件、400 项测试、类型检查、
生产构建及三个原生回归脚本通过；构建保留既有的第三方兼容与包体积提示。
