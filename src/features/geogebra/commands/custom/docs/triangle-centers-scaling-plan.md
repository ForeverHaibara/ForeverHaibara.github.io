# TriangleCenter 全范围扩展前的性能、图求解与维护计划

日期：2026-11-01。基于工作区 `1f802e3`、本地 ETC 缓存和当前生成数据的只读分析；初次规划轮未修改解析器、选择器、运行时或正式配方；后续实施记录见文末。下文区分已经测到的事实、代码推导的风险和后续设计建议。

**建议先做来源预检、可观测性和阶段缓存，再改图求解；之后用全量候选图研究跨页闭包，最后分批发布数据。** 不能直接把默认 `--parts` 改成全部页，也不应靠收紧候选、坐标长度、锚点数或深度来取得性能指标。

本文是下一阶段的行动计划。[原计划](triangle-centers-plan.md)保留数学约定和历次接入记录；其开头数量及一些早期限制已经不是当前状态。当前格式契约见[数据 README](../data/triangle-centers/README.md)。

## 2. 性能问题与复杂度判断

记 `V` 为中心数、`H` 为候选配方数、`D` 为候选依赖引用总数、`S` 为样本形状数、`A` 为公式 AST 总规模。最终已选图的边数远小于候选引用数，必须同时记录二者。

### 2.1 提取阶段的重复工作

`extract_entry` 已有关系文本视图，随后 combo、Shinagawa、坐标解析又分别调用 `coordinate_text(fragment)`；某些条目在 `read_page` 为 incidence 再解析关系文本。建议一次生成**两种有不同边界语义的视图**，并传递给各规则。不能为省事把两种视图合成一个：上标、下标和 HTML 换行处理会影响公式正确性。

公式目前每次求值都会再 `validate_formula`，后者重新建 AST、遍历节点并建立父索引。应产生不可变的已验证公式 IR，缓存旋转后的 AST、齐次度及规范形式；只替换数值环境。每个三角形的边长、角度、Conway 环境可计算一次。需要缓存失败结果，避免相同不支持语法一再解析。`canonical_formula` 的加/乘展开也需审计长链上的列表拼接成本，避免长式隐藏二次复杂度。

### 2.2 闭包与替换反复扫全图

当前闭包每轮扫描 pending 的全部候选，并重算已选图的深度、长度、共轭层数和全部样本坐标。即使一次全图 DFS 为 `O(V+E_selected)`，替换约 `K` 次就是 `O(K(V+E_selected))`，而不是一次线性检查。当前 2,604 / 1,879 次全图计算已经足以把这一风险变成实际开销。

剪除一个坏点时又用全体 selected 反复寻找依赖者；应有反向依赖索引，BFS/DFS 只访问受影响后代。`numeric_coordinates` 单次会复用成功坐标，却不记忆失败结果；失败依赖被多条路径引用时会重复求值。需要按一次快照缓存 `finite / ideal / undefined / unknown`，不能让 undefined 冒充“未访问”。

现有 refinement 使用替换前的 `refine_coordinates`，之后才做终局复查；终局修理主要换同操作的 J/I，否则剪除依赖者，不重新开放所有被剪掉点的其它构造。固定最多 30 轮也不是随规模可靠的收敛机制。新增页面可能让原来可用的好点丢失，或者存在其它构造却因一次剪枝而未回来。这些是代码路径上的风险，尚未用全量解证明发生频率。

### 2.3 候选数量本身也要压缩，但不能丢搜索空间

若条目已有可靠、输入闭合且数值筛查通过的显式四点交点，可直接采用 GeoGebra 原生四点交点所对应的构造，不必枚举十条线。后续将这一路径前置；仅在它不可用或明显有更优替代时延迟探索线表，必要时继续开放备选。

当前线表先取最多 10 条线，再枚举不共端点的线对，最多产生 45 个 J；完整线表另外还用于坐标证据。增加页数后 H 可能比 V 大很多。降低 10 这个数会损失可能唯一可用的线对；直接把上限改成全部再枚举，也会制造 `O(L²)` 膨胀。

后续可保留“目标的 incidence 线集合”这一紧凑节点，**按需生成**可用线对，缓存端点及线几何；先试有独立证据、条件较好或开销较小的线对。缓存相同 J 的端点/两线交换等严格等价形式，并保留合并后的全部来源证据。有限点与方向的类型不能在这种正规化中混淆。延迟生成必须在相关依赖变化后继续开放，记录未探索候选；不能把“本轮只看了前若干条”报告成数学不可解。

以两形状上的归一化线系数或交点聚类减少重复数值筛查可以做实验，但它只是数值筛选，不能证明不同文本关系在所有三角形上恒等。不能据此永久合并几何定理。

## 3. 合适的图模型和求解顺序

### 3.1 用 AND/OR 依赖模型，而非普通最短路

同一点的多个候选是 OR；一条 `J p q r s` 需要全部输入，是 AND 超边。等价实现是二部图：中心节点 → 使用该中心的候选节点 → 候选目标。

第一步只求“从原生输入、有效种子和坐标锚点出发能否闭合”的最小不动点。给每个候选保存**未就绪的不同输入数**和反向 watchers；输入首次就绪时更新其使用者，计数归零后再作类型和几何筛查。去重后的输入用于 readiness，原始参数位置仍用于运算和长度计算。无反复撤销的这一阶段可望把结构调度做到 `O(V+H+D)`，数值计算另计。

这个复杂度只适用于固定候选、固定输入状态下的可达闭包，**不意味着带替换、环约束、退化和多个成本目标的完整选择也是线性**。也不能直接使用普通 Dijkstra 保证全局最优：共享子图、最大路径深度/共轭层数和根操作风险不是一个简单可加权重。

### 3.2 分开可达性、配方质量改进和数学确认

建议先保留一个可闭合、无环的构造见证，再用启发式优先队列作有限的质量改进。目标是兼顾效率与近似优秀性，不求最优路径/构造；不同 Part、参数或规则下选出不同正确配方可以接受。质量至少分开记录来源强度、操作域风险、依赖的风险、关键路径深度、共轭层数、唯一子图/表达式成本。现有 `quality` 主要看根操作，不能自动体现下游包含坐标或奇异交点的风险。

初期不追求全局最少锚点或最少共享对象。对候选使用可解释的稳定排序；遇到深度/共轭等资源约束冲突时，评估是否需要保留少量非支配状态。若采用 Pareto 状态，先量出标签增长，不能许诺状态数有常数界，也不能无声截断标签后声称完整搜索。

每次拟议替换作为事务：检查新输入类型和目标是否沿所选依赖可达自身；计算新目标及**受影响后代**的深度、成本、样本状态与证据，全部成立才提交，否则回滚。只降低根操作风险仍可能加深后代或使依赖线退化。一次提交后，按版本使相关候选重新入队；终局保留一次完整、独立的拓扑/类型/数值检查。

必须把构造依赖和验证依赖分开建索引。第三支持线、坐标已知 incidence、combo 对照的已有目标、Shinagawa 对照坐标都可能影响候选是否合法，即使这些点并不出现在配方的 `references`。只监听构造参数会漏掉“支持线后来闭合”或“参考坐标后来变化”的事件。

### 3.3 SCC、弱连通分量各有用途

把候选超边投影成“目标依赖输入”的有向边后，SCC 可定位互相引用的核心，压缩图可帮助安排外部输入就绪顺序；但一个 SCC 中有很多**互斥的备选边**。候选图中有环，不代表所有构造都循环，更不代表最终不可能无环；一个坐标锚点或外部替代定义就可能启动它。原生锚点、已闭合节点作为外部终端处理。

弱连通分量适合诊断和互不依赖部分的分工，不等于必须给每簇固定锚点配额。候选关系丰富时可能有巨型弱分量甚至巨型 SCC，不能把“按 SCC 分块”当作万能提速。须在关系基线闭包后再看残余图，结合局部循环、未满足超边和可用锚点分析。当前没有默认锚点上限，应保留这一行为。

如研究“哪个坐标锚点最值得先加入”，应以加入后实际解锁的 AND 闭包作为收益，而不是把普通图的直接出度当收益。此类选择含相互补足效应，宜用实测边际收益的启发式并保留所有可靠候选；不把最优最少种子的求解列为前期必须完成的项目。

## 4. Part 是输入集合，不是永久求解分区

长期结构应是：

```mermaid
flowchart LR
  H[逐页 HTML 与来源预检] --> C[可复用的逐条目候选 IR]
  C --> U[选定 Part 集合的候选并集]
  U --> Q[依赖闭包与局部质量改进]
  A[原生状态、atlas、种子和策略] --> Q
  Q --> V[完整校验与差异报告]
  V --> O[原子发布的运行时块]
```

应允许“全量候选分析”和“发布部分目标编号”分开。前者可以用后段定义改善前段点；后者只输出所发布目标及其必要的扩展依赖，不把未审核页面的任意点自动变成公开支持。输出依赖必须齐备，不能仅按目标所属页过滤配方。

缓存至少分三层：

1. **来源/提取缓存**：按原始页及条目 hash、切块/文本视图/规则版本存 IR，包括空提取结果和异常。当前提取会过滤 unavailable/deferred 引用，若保持这种行为，状态文件也必须进入 key；更好的后续拆分是提取保留原始候选、状态筛选放到求解层。
2. **公式缓存**：正规式、语法版本、旋转 AST、齐次度、规范形式；样本数值另以三角形/atlas 版本为 key。有界缓存并统计命中率和内存，不把所有大 AST 无限常驻。
3. **求解与验证缓存**：显式 Part 集合、候选内容、种子、原生有限/方向状态、atlas、来源例外和选择策略共同决定结果。几何筛查还需记录读取了哪些点及其 recipe/坐标版本。不能只以“页号”缓存筛查结论。

新增 Part 可能带来新候选、改变旧点的更优定义、合并 SCC 或未闭合簇；要传播到构造依赖及证据读取的反向闭包。被标为“缺页”的失败也要有 watcher，页补齐后重新尝试。修改/删除规则或原生状态时也必须使旧的成功结果失效。初期可采取“缓存提取 + 全局重求解”的可靠过渡；等调度和版本索引稳定后再实现局部增量求解。

小规模失败、大规模成功是合理现象；不能把小规模下的 unresolved 永久写成 seeds 的 `SKIP`。明确的源错误/数学不可绘状态、缺页、未实现规则、预算不合格和本次尚未闭合必须分开。

扩大输入后，**可构造性的理想模型**可以单调增加，但当前带预算、择优替换、几何筛查的最终输出未必单调。每批都要比较旧编号：新增/丢失/配方变化/风险变化/实际成本变化。已有编号的几何含义应保持；不能仅凭“输出了同样多的行”验收，也不应为掩盖选择器不稳定而不断增加固定种子。

## 5. 可观测性、断点与工程组织

建议先建设统一的阶段报告器，控制台每 2–5 秒汇总一次、阶段结束必打印且立即 flush；非交互终端保留完整日志行。持久 JSONL/JSON 供比较，详细候选原因可按目标查，不默认逐条刷屏。

最少输出：

- 运行开始：run id、代码/规则指纹、完整 Part 集合、输入 hash、原生/种子/atlas 版本、所有限制的有效值、冷/热缓存状态。
- 来源预检：页数、条目边界/唯一编号、重复/错号/坏锚点、已隔离项、来源例外命中。
- 提取：当前页及 X(n)、已处理/总条目、各操作候选数、坐标 AST 总节点/最大深度、缓存命中、耗时与慢条目。页数百分比不能充当剩余时间估算；长式密度不同。
- 求解：已闭合、pending、候选就绪/失效数、队列与 dirty 集大小、尝试/成功/回滚替换、剪除与重开的点、SCC/残余簇、受影响后代数；阶段及累计时间。
- 几何：每种样本 finite/ideal/undefined/无验证证据数、冲突与病态程度、无法提供第三支持线的数量。不得把全部失败合成一个 `unsupported`。
- 结束：覆盖分母与状态拆分、操作/深度/长度/扇出分布、最慢十项、缓存体积和峰值 RSS、输入/输出差异及可重现命令。

求解没有稳定的总任务数时显示队列、速率和最近进展，不编造“99%”或确定 ETA。长阶段开始/结束事件必须可见；允许按 X(n) 查询拒绝原因和依赖见证。

检查点按页/提取阶段持久化，原子写临时文件再改名。一次 Part 28 失败后，应能保留 1–27 页成功的提取结果；但整次正式构建仍应以失败结束，不悄悄发布缺页产物。`build` 先在 staging 验证所有块及 manifest，再一次替换正式输出；`check` 不改正式数据。中断可重启，临时/旧版本缓存不能混入新版本，两个构建进程应避免争写同一输出。

可以把目前一个脚本的职责逐步分为来源/候选提取、公式 IR、图调度、数值验证、报告/输出等小模块，但每次拆分保持命令兼容。默认不引入数据库、自动联网同步或分布式任务系统。优先去重和缓存后，再依据 CPU profile 决定是否需要按页的有界多进程；线程数增加不能替代算法改进，Windows 子进程的启动、传输和内存成本也要测。

## 6. 离线图变快后，还需控制客户端计算图

客户端 `prepareTriangleCenter` 已缓存数据块与加载 Promise，但没有按一次请求记录已完成的依赖节点，菱形依赖会被重复走访。可以先采用请求级 `visiting + prepared`，再按不可变数据版本复用闭包；保证环和失败仍可重试。跨块并行/预取需要与 cycle detection 的上下文分开，不能把共享 Promise 等待造成的死锁当作依赖闭合。

`render` 目前递归拼字符串，没有按中心共享子表达式。JS 层 memo 字符串只能减少重复生成，**不会减少字符串被复制到父式、GeoGebra 重复解析或构造对象的数量**。因此需要评估显式的、带类型的中心计算 DAG，再按复用次数和实际代价选择 `bind`/命名中间对象。边长、角度、Conway 公共量也应尽可能共用。

现有 `bind` 能捕获中间量，但不是整个中心图的自动公共子式消除；命名后端还有 128 个 binding 节点、50 万字符等转匿名条件。TriangleCenter 已放开长匿名输出的总字符限制，不能因为离线长度估计通过就假设真实引擎成本可接受。需要测：

- 唯一中心/公式节点数与树式重复次数、实际编译字符和辅助对象数；
- 首次/跨块准备、编译、引擎创建、连续拖动的 P50/P95/尾部；
- Low/Medium/High 与当前实际 eligibility 的差异，以及何时退回匿名；
- 嵌套、同一语句多次引用、不同 ABC/顶点顺序、输出标签已存在时的行为；
- 导出重开、拖动、撤销、删除、失败回滚和 helper 清理。

重心/三线、理想方向、复/条件域必须保持原数学约定。特别是负数底的分数幂、浮点溢出、接近理想点和近退化三角形，Python 与 GeoGebra 的实数语义可能不同。不能靠固定坐标 epsilon、任意约因子或随机扰动扩大公式定义域；对病态样本可增设高精度独立对照，符号/精确验证按高风险规则使用，不对所有点强做全符号化简。

离线数值筛查本身也需审计尺度：当前若干线长/向量判断使用绝对阈值，两种 atlas 又都处在相近坐标尺度。后续加平移、镜像、顶点轮换、整体缩放与病态形状的测试；在证明齐次度一致后，可研究以归一化边长求权重、再映回世界坐标，减少高次公式上溢/下溢。公共比例约去不改变定义域的条件必须写清。病态/无法确认应是一种诊断状态，两样本上的近零坐标和不能单独证明该点恒为理想点，巨大有限数也不能自动证明它不是理想点。

## 7. 下一轮到全范围的执行批次

每批可单独提交、回退和验收；优化批与增加覆盖的批次分开，以便解释变化。

| 批次 | 交付 | 验收门槛 |
| --- | --- | --- |
| P0：来源与性能可见 | 廉价全页标题预检、阶段计时/计数/心跳、结构化报告、固定四页基线 | 无须解析全部公式就能报告上述来源异常；明确失败阶段；重复运行记录完整且不改配方 |
| P1：复用与检查点 | 一次条目多视图、验证后公式 IR、样本环境/成功失败缓存、逐页提取缓存 | 四页 `check` 逐字一致；冷/热及仅改一规则分别计时；未变页面不再解析；更改 atlas/种子/状态可正确失效 |
| P2：事件驱动图求解 | AND/OR readiness、反向构造/证据索引、局部替换事务、失败点重新开放、终局完整校验 | 四页旧行为对照；顺序/增量等价；无逐个替换的全图 DFS；全图校验次数与替换数脱钩；数值结果和域契约无回退 |
| P3：完整候选图与来源例外 | 所有页的来源审核/隔离记录、全量候选缓存、SCC/残余图报告、全量 dry-run | 不能跳过坏页后报全量成功；对早期点的改善/损失可解释；扩展仍使用相同或更完整搜索空间 |
| P4：客户端 DAG 成本 | 重复闭包消除、选择性绑定/公共量共享实验、尾部构造基准 | 代表点在真实引擎中值/拖动/生命周期通过；明确匿名回退与长式成本；不增加启动全库加载 |
| P5：分批扩大正式覆盖 | 按依赖簇及操作域组织的发布批，补规则/特殊族，逐批差异报告 | 每批先全图验证再按风险分层抽测；无丢失的旧编号或有明确审阅理由；来源、配方、抽测可追溯 |

P3 的“全量候选 dry-run”与“全部点支持”不是同一验收项。扩大语法、支持新变换、解决复数/非唯一对象仍可能需要独立数学设计。最终应做到对全部实际条目都有状态说明；对可以提供唯一实有限输出的点逐步扩大构造覆盖，并为理想/条件/复对象给出正确状态。

## 8. 验证矩阵与决策门槛

### 8.1 等价性与正确性

- 优化前后对同一语料、同一参数逐字比较 chunks，并比较候选集、来源和拒绝原因。算法改良若有意更改配方，单列审阅，不混入“纯性能优化”。
- 小型图反例覆盖：纯循环无起点、循环中的替代外部起点、需要多个输入才解锁、向后编号引用、菱形共享、替换导致后代超深/共轭超限、理想输入类型变化、第三线晚到、失败/删除后有替代定义、超过 30 个独立修理事件。
- 同一语料的冷/热缓存应恢复相同候选且通过相同正确性检查。改变 Part、参数、规则或求解路径后，允许构造变化；比较覆盖、域风险与成本，不把规范的唯一配方当目标。
- 比较 `S={3,4,5,37}` 与 `S+新页`，追踪同一旧编号的构造、风险和运行时成本；再比较全量候选求解后投影到 S 的结果。缺页失败不得被持久缓存为永久无解。
- 继续使用现有 Python 规则测试与 TS 编译测试；保留真实引擎分层抽测。当前 35 点 smoke 对早期关系族有价值，尚不足覆盖目前长坐标、F/V 和条件公式的所有风险。

### 8.2 性能实验

固定源内容与规则版本，禁止在性能比较时更改深度、共轭、线表候选、坐标锚点或支持操作。将 cProfile 的定位运行与正常计时分开。主基线在机器无其它本任务 CPU 进程时运行，记录 Python/依赖版本和峰值 RSS；足够稳定后做三次报告中位数与范围，避免反复运行没有新增信息的昂贵全量测试。

基准至少包括四页、四页加一页、全量缓存；冷提取、热提取重求解、只改一个条目、只改一解析规则、只改原生状态/atlas、只改选择策略。规模轴同时报告 V/H/D/A，不能只画“Part 数→秒数”，因为页面公式和关系密度差别很大。

工程上优先验收**工作量消失了没有**：未变页的解析次数为零；每个不变公式不重复建 AST；每次替换仅更新反向闭包；终局全图检查是固定阶段，而不是 K 次；缓存和队列的内存可测且有界。经过这些改动再给全量冷/热耗时订预算，当前不承诺“37 页只需四页的某个固定倍数”。

如果全量 dirty 区域本来就很大，允许退回一次规范的全图求解；不能为坚持“增量”而产生更慢或不一致的路径。如果完整候选内存成为瓶颈，先紧凑表示线表/引用和共享证据、按页落盘，之后再讨论二进制格式；当前 258 KB 的运行时数据并不是首先要解决的离线瓶颈。

### 8.3 开工优先级

下一轮先交付 **P0 + P1 的最小闭环**，保持现有四页产物不变；据其 profile 再实施 P2。来源异常的检查和缓存可以先服务全量诊断，正式配方继续保持现状。P2 稳定后扩大 Part 集合，并在相同图上测深度/共轭约束的饱和情况；这些约束应根据可正确构造的运行时 DAG 来调整，不能成为掩盖求解成本的工具。

复测命令（仓库根目录；现有缓存不联网、不改 chunks）：

```sh
python scripts/geogebra/tools/triangle_centers/triangle_center_import.py verify
python -u scripts/geogebra/tools/triangle_centers/triangle_center_import.py check
python -u -m cProfile -o .cache/triangle-centers/planning/planning-baseline.prof scripts/geogebra/tools/triangle_centers/triangle_center_import.py check
python -c "import pstats; pstats.Stats('.cache/triangle-centers/planning/planning-baseline.prof').strip_dirs().sort_stats('cumulative').print_stats(25)"
```

本轮临时 `planning_probe.py` 提供阶段包装和纯函数 memo 实验；`planning_topology.py` 提供带异常隔离的结构诊断及逐页检查点。它们是工作区实验，不是新的正式导入接口；诊断结果不得直接交给 `build`。长期保留的结论在本文，临时缓存可按需清理。
