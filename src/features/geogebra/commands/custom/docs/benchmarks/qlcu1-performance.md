# QLCu1 坐标方程性能实验（2026-10-16）

直接代入四点坐标的方程，在本次固定视口实验中使更新耗时中位数减少约 **17%～19%**；创建耗时没有明显收益。它不是正式工具实现，不能据此宣称匿名绑定是全部瓶颈。

后续人工测试改用另一个更短的式子：由有向角 `∠APB=∠DPC`（模 180°）直接写成 `cross(PA,PB)·dot(PD,PC)−cross(PD,PC)·dot(PA,PB)=0`。叉积先展开为一次式，因此结果至多三次，没有分母，普通 A/B/C/D 标签下展开为 **230 字符**；在参考构造失效的平行四边形等情形中也允许保留降次极限。四点重载在 `library.json` 中使用 `qlCubicCoordinates`，改回 `qlCubic` 即恢复原方案；切换后需重新创建曲线。此新短式**没有使用本表计时**；原实验入口仍明确比较旧构造与 11,813 字符长式，避免混淆数据。

## 修改范围与正确性

- 正式 builder 只修复 `midpointCubic` 中的 `2*${c}` 为 `2*(${c})`。三参数重载传入的 c 是复合表达式，原先漏乘了一份 `n·M`；四点重载传入单变量，几何公式不变。
- 原生回归：`M=(1,1), S=(2,1), n:x=0`，正确曲线在 `(0,1)` 的方程残差为 **0**，修复前为 −1。
- 实验候选位于根目录 `scripts/geogebra/browser/geogebra-qlcu1-equation.ts`。输出 **11,813 字符**，只有坐标提取、四则运算、非退化守卫和一个 `ImplicitCurve`；没有 `Zip/Element`、复数转换或辅助几何对象。现有展开为 **526 字符、五层 Zip/Element**。
- 两种原生曲线在三组 C 坐标下，按十个确定三次多项式的三角形格点核对比例一致性；相对误差最大约 `1.55e-13`。独立单元测试另外核对共轭中点定义在平移、旋转和缩放下的一致性。
- 非退化守卫保留有限密克点、非零 κ 和确定牛顿线的要求；此次实验没有为新增退化延拓作承诺。

## 方程

以下短记号只用于推导，实际交给引擎的表达式已经全部代入 `x(A), y(A), …, x(D), y(D)`，没有这些绑定变量。

把点视为复数，先按实数四则运算展开

```
M = A + (B-A)(D-A)/(B+D-C-A)
κ = (A-M)(C-M) = u + iv
```

设 `U=(A+C)/2`、`V=(B+D)/2`，直接从坐标求牛顿线的齐次系数：

```
nx = Ay+Cy-By-Dy
ny = Bx+Dx-Ax-Cx
d  = ((Ax+Cx)(By+Dy)-(Ay+Cy)(Bx+Dx))/2
c  = d + nx Mx + ny My
wx = x-Mx, wy = y-My
F  = (nx wx + ny wy + 2c)(wx²+wy²)
     + nx(u wx+v wy) + ny(v wx-u wy)
```

候选最终调用 `If(有效性条件, ImplicitCurve(F))`。没有计算不动点、平方根或反射轴方向。

## 条件与计时口径

- 当前机器的 Codex 内置 Chromium 155；引擎 API 报告版本 **5.4.920.0**。同一个原生 applet 交替执行两种方案。
- 浏览器视口 **1280×1000**、DPR 约 1；applet 为 **800×480**，实际绘图 canvas 为 **799×426**。完整画布在屏幕内，代数面板关闭，坐标范围固定为 `[-5,8] × [-4,6]`。
- 初始点 `A=(0,0), B=(4,0), C=(3,3), D=(-1,2)`。仅移动 C，轨迹为 `C_i=(3+0.4 sin(2πi/12), 3+0.3 cos(2πi/12))`，`i=0,…,11`。
- 先验证等价性，再分别预热两种方案并各更新两次；不计 applet、原生命令模块加载或站点编译。每个计时 case 都重建四个点，只保留一条待测曲线。
- **3 轮**，顺序为现有→直接、直接→现有、现有→直接。每种方案／重绘模式有 **3 次创建、36 次坐标更新**。
- `creationMs`：提交已展开的原生命令到异步求值返回。`updateMs`：调用原生 `setCoords` 到返回。`frameMs`：从同一更新开始，正常重绘时再等待两次 `requestAnimationFrame`；这是浏览器帧边界口径，不是 GPU 完工时间或真实鼠标事件的延迟测量。
- 关闭重绘使用原生 `setRepaintingActive(false)`，不据此断言引擎内部完全没有路径或绘图准备工作。
- 所有样本均保留，包括首轮现有创建的较大值及末轮耗时上升；中位数不作手动剔除。窄侧栏中的前期试跑未混入此表。

## 结果

单位为毫秒；创建是 3 次的中位数，更新是 36 次合并样本的中位数。P95 用线性插值。

| 指标 | 现有四点方法 | 完全代入坐标方程 | 耗时变化 |
|---|---:|---:|---:|
| 创建，关闭重绘 | 2772.1 | 2805.1 | +1.2% |
| 创建，正常重绘并等待两帧 | 2838.2 | 2878.0 | +1.4% |
| 单次更新，关闭重绘 | 2218.0 | 1801.7 | −18.8% |
| 单次更新，正常重绘（API 返回） | 2177.9 | 1804.8 | −17.1% |
| 单次更新，正常重绘并等待两帧 | 2182.7 | 1808.6 | −17.1% |
| 更新 P95，关闭重绘 | 2377.1 | 1898.0 | −20.2% |
| 更新 P95，正常重绘并等待两帧 | 2505.1 | 2160.4 | −13.8% |

**解释**：约长 22.5 倍的直接方程确实减少了此构型附近的动态更新成本，但没有让作图变得流畅，也没有显示出创建优势。不能把改善全部归因于 Zip 复制：候选同时改变了中间对象表示、重复计算和曲线包装。此次没有测量手动构造 M／不动点／牛顿线的三参数方案，也没有做全部退化构型或跨设备测试。若要定位剩余瓶颈，下一次应隔离系数计算与曲线生成、比较只绑定数字而不包装整条曲线的方案。

- 实验入口：`scripts/geogebra/browser/geogebra-qlcu1-benchmark.html`、`scripts/geogebra/browser/geogebra-qlcu1-benchmark.ts`。
- 独立方程生成器及测试：`scripts/geogebra/browser/geogebra-qlcu1-equation.ts`、`scripts/geogebra/browser/geogebra-qlcu1-equation.test.ts`。
