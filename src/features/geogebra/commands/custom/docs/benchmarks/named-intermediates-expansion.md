# 命名中间量第二阶段筛选（2026-10-29）

使用 `geogebra-named-execution-smoke.ts` 在嵌入式 GeoGebra Classic 中，对同一输入分别运行匿名与命名路径，检查输出对象类型、是否有定义、显示方程及输入变化后的更新。创建时间包含辅助对象和输出对象；更新时间包含设置输入与读取结果。下表为单次浏览器样本，受预热和调度影响，只用于筛选，不当作稳定的性能基准。

| 候选重载 | 匿名／命名创建 | 匿名／命名更新 | 结果 |
|---|---:|---:|---|
| 三次曲线 `OrthicAxis(F)` | 89／41 ms | 12／8 ms | 直线类型、方程和动态更新一致；退化样本也一致 |
| `Poloconic(l,F)` | 423／279 ms | 36／10 ms | 双曲线类型、方程和动态更新一致；退化圆锥曲线样本也一致 |
| 方向约束 `CircularCubic(A,B,C,D,E,F,l)` | 418／257 ms | 40／7 ms | 隐式曲线类型、方程和动态更新一致 |
| 七点 `NodalCubic(...)` | 774／656 ms | 337／33 ms | 隐式曲线类型、方程和动态更新一致 |
| 五点 `NodalCubic(...)` | 496／419 ms；另一次 741／747 ms | 341／56 ms | 隐式曲线类型、方程和动态更新一致；创建收益受运行波动影响 |

以上五种重载启用命名路径。`Poloconic` 与方向约束 `CircularCubic` 还分别用线段输入复核，类型、方程、动态更新一致，创建及更新均更快。`NodalCubic` 的其它重载暂不启用，因为其约束和基底不同，且尚未单独验证。

| 未启用候选 | 观察到的问题 |
|---|---|
| `ThirdIntersection(F,P,Q)` | 命名路径把输出从点变为向量，虽然创建更快 |
| `CircularPolarPoint(F)` | 命名路径把点变为向量；一个样本还改变了未定义状态 |
| `CayleyBacharachPoint(...)` | 命名路径把点变为向量 |
| `Polar(P,F)` 的三次曲线重载 | 普通样本更快；退化样本中匿名路径未产生输出，命名路径返回错误，未满足同一执行语义 |
| `CubicPencil(F,G,P)` | 样本中创建约 125→171 ms，变慢 |
| `PivotalCubic(...)`、`NonpivotalCubic(...)` | 分别约 466→3019 ms、575→4700 ms，明显变慢；同类三角形三次曲线保留匿名路径 |

这些反例说明，仅凭 `bind()` 值是数值或函数仍不足以保证 GeoGebra 的结果类型与运行语义不变。白名单按 builder 及必要的输入重载保守扩展。当前机制不尝试对单个调用选择性物化一部分绑定，也不自动推广到其它同名命令的重载。
