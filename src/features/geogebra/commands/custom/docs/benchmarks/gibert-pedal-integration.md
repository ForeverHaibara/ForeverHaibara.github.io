## 问题定位与方案选择

旧生成器先把重心单项式代入九个通用世界坐标框架量，再生成每个笛卡尔系数。Q018 的命名文本保守估算约 878,096 字符；仅在最终表达式上使用 Horner 并不能解决这个中间展开。Q020 的旧配方也超限。它们不是因为几何定义本身需要这么长的表达式。

已有[垂足推导](gibert-pedal-derivation.md)证明了两条下载式与几何定义的约分分子相同。该证明本轮重新运行通过。生产实现采用与其等价的**相似标准三角形多项式**，而没有把含可动曲线变量的投影、交点和垂心当作普通数值辅助量。此处既不调用运行时 CAS，也不调用 Locus 或数值插值。

### 局部方程与非零因子

记 `A=(0,0), B=(1,0), C=(t,h)`，`h≠0`。在来源齐次重心式 `F` 中代入：

```text
a2=(t-1)^2+h^2, b2=t^2+h^2, c2=1
u=h*(1-X)+(t-1)*Y, v=h*X-t*Y, w=Y
```

Q018/Q020 均有且约去公共因子 `h^5`，剩余为八次多项式 `L(X,Y)`。生成器仅生成它的 45 个三角基系数及共享数值子表达式；系数按 `(0,0),(0,1),(1,0),…,(8,0)` 排列。共享节点最多保留 80 个，其余离线内联，给现有绑定节点预算留出阶段空间。这里的 80 是作者侧的结构选择，最终仍必须通过真实编译预算。

独立检查器完整重建多项式并验证 `h^5*L=F_substituted`，检查数值节点不含 `X,Y`，并在一般、等腰、反射和等边三角形上检查非零系数。没有约去依赖曲线变量的因子；边、外接圆和顶点处的代数闭包由原始多项式保留，几何有理构造的分母不进入运行时有效性条件。

### 世界坐标转换分为数值阶段

对实际输入令：

```text
dx=Bx-Ax, dy=By-Ay, s=dx^2+dy^2
ex=dx/s, ey=dy/s
t=ex*(Cx-Ax)+ey*(Cy-Ay)
h=ex*(Cy-Ay)-ey*(Cx-Ax)
X=ex*(x-Ax)+ey*(y-Ay)
Y=-ey*(x-Ax)+ex*(y-Ay)
```

依次绑定局部系数、`L(ex*x+ey*y,-ey*x+ex*y)` 的旋转缩放系数、再平移后的世界系数。转换使用静态二项式权重和前一阶段的数值依赖，避免把所有替换一次展开。最后才组成 `ImplicitCurve`。阶段中的所有辅助值均为原生动态数值对象；JavaScript 不读取输入点坐标。

最终乘以仅依赖三角形的 `s^(degree/2)`，本例为 `s^4`，恢复长度归一化造成的方程尺度。未恢复时原生 XML 已含非零系数，但显示方程会被四舍五入成 `0=0`，也不利于引擎的绝对容差。此尺度因子在非退化三角形中非零，不增加或删除曲线分支。它不能解决所有大坐标的消差问题。

有效性条件为三输入定义、非共线、`s!=0`、局部系数平方和非零。共线或重合时未定义，恢复一般位置后继续更新；等边三角形中的这两条仍为非零多项式，按既有约定保留。128 的上限统计绑定组节点，一个系数数组的绑定组会创建多个辅助对象；没有将辅助对象数误当节点数或绕开限制。

## 可替换的实现入口

`curves.json` 保留来源方程、次数和测试点，新增可选 `backend`。未指定的 190 条继续使用原有 `relatedCurves.json`；本轮未改写该 5,240,692 字节文件。新两条选择 `similarityPolynomial`，其生成数据合计 16,050 字节，位于独立的 `relatedCurveCircuits.json`。

`builders/relatedCurveBackends.ts` 的注册表是实现选择入口。以后可以为某条曲线选择手写构造或变换后端，不必强行伪装成旧的生成配方。选择仍只根据编译期字面量编号发生一次，命令池只有一个 GibertCurve，不生成几百个 `If` 分支。未知后端失败，不静默回落。

新增后端需要在 TypeScript 注册表与离线生成器允许列表中同时登记，并提供与来源式的独立核验。所有实现仍使用既有 typed bind、命名白名单、原生类型检查与生命周期。不能用 JavaScript 坐标快照、隐藏 CAS 状态或新的私有辅助标签机制替代这些约定。新相似坐标生成器目前只接受边长平方齐次系数；含边长奇数次幂或其他定义需另行转换和验证。

| Q020 / High / `"Q020"` | 104,539 字符 | 14.71 s | 45.85 ms | 217 |

总对象包含 A/B/C、输出及 213 个辅助数值对象。移动计时是 `setCoords` API 返回耗时，不是完整绘制帧率。编译长度和可拖动性已改善，但首次构造仍明显耗时；不能把“通过编译”理解为所有交互都即时。保存文件分别约 16.7/17.4 KB。原生类型、随 C 改变、有限中心、Q018 三个垂足、共线/重合恢复、等边、原子撤销重做、导出重开后的依赖和辅助清理均通过；Q020 另核对三个旁心。

专项测试在旋转、反射、平移缩放、近等腰和近共线（底 6、高 0.05）五组三角形上，比较网格、边及边附近、外接圆及圆附近共 8 个位置，并检查三个顶点。参考值从**原始来源方程以精确有理数离线计算**，独立于电路生成结果；只在写入测试夹具时舍入一次。

### 未采用的原型

- 小型二元函数能被原生 `ImplicitCurve` 接受，但将这两条的紧凑 Horner 函数代入世界坐标仍长时间无响应。短函数文本不能代表原生符号处理成本低，生产后端不使用这一方案。
- 将整组系数绑成原生数值列表以减少对象数的尝试，在浏览器观察窗口内超时，未完成等价与生命周期核验。本轮采用已经通过验证的逐系数数值对象，不将列表原型作为性能结论。
- 不恢复长度尺度的版本可以生成非零 XML，但显示 `0=0`；已修正。没有用显示文字替代数学恒等式或非零检查。

## 后续改进顺序

1. **先复用新后端评估 Q070/Q109，再评估 Q007。** 每条独立生成、精确证明和原生抽测；现有证明只涵盖 Q018/Q020，不自动宣布其他高次曲线已支持。评估生成时间、编译文本、辅助对象数、首次构造、拖动及文件成本。
2. **保留定义和变换结构。** 可为垂足/反垂足等几何运算建立多项式系数运算层，在生成时共享低次数乘法与行列式；或为反角共轭、反演登记变换配方。先证明清分母和约因子的结果与目标式相同，尤其分辨基础点、边和无穷远附加分支。不能简单对目标逐点作有理映射后宣称得到整个代数闭包。
3. **减少创建成本与世界坐标消差。** 选择性保留确有复用的 scalar 节点；比较逐系数、有限分块与更稳定的局部表达方式。任何函数或列表候选先在隔离原生引擎验证，不能只按对象数或字符串长度决定。若世界坐标引擎仍强制展开，需明确它对大平移的精度边界。
4. **再处理旧生成文件的重复和加载体积。** 旧文件大量存放相同重心单项式模板的世界转换；可以把模板按单项式结构共享，记录只存来源系数及模板引用。也可按后端/批次拆分作者数据。先检查真实 bundle/gzip 与加载方式，再决定是否引入异步加载；同步编译接口不应为了拆 JSON 被悄悄改变。本轮保留旧曲线行为，避免一次迁移 190 条。
