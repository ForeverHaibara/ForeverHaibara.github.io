# TriangleCenter 扩展：数据、编译与分批接入计划

状态：2026-10-31 从 ETC 第 3、4、5、37 部分生成 6340 条配方，其中 6323 条由文本规则自动取得。现已读取标准线表及更多交点写法，并用两种形状的构建期坐标样本筛查线对；其它页面和特殊变换仍待分批处理。

## 1. 已确认的边界

- [GeoGebra 手册](https://geogebra.github.io/docs/manual/en/commands/TriangleCenter/)写明 `TriangleCenter(A,B,C,n)` 原生支持 `n < 3054`。实施时在项目实际使用的引擎核对 3053/3054 的行为；在此之前以 1–3053 为原生区间。文件自带工具仍优先于站点工具。
- [ETC 第 37 部分](https://faculty.evansville.edu/ck6/encyclopedia/ETCPart37.html)尚未填满导航标称的编号区间，且会继续更新；爬取时以实际 `X(n)` 条目计数，不能由导航的区间上限推断现有八万余条或生成空记录。设计容量按将来超过八万条预留。
- [ETC 更正页](https://faculty.evansville.edu/ck6/encyclopedia/Corrections.html)记录了 2026 年第 35、36 部分的大范围重编号。仍由人工更新、Git 记录变更，但每次人工导入须核对新条目及受影响的旧编号。
- 已读本站 [工具规则](../README.md)、[实现计划 §2](implementation-plan.md)、[三次曲线退化约定](cubic-tools-roadmap.md)、[GibertCurve 维护说明](related-curves.md)和[命令编译器](../commandCompiler.ts)。本站命令只在站点输入栏编译为原生依赖；原生输入栏和对象脚本不变，保存后不依赖网站运行时代码。已保存对象不会因配方更新自动改写，用户需删除并重建结果。

## 2. 公开行为与命令管线

| 第四参数 | 处理 |
| --- | --- |
| `1`–`3053` 等已知原生区间的整数字面量 | 保留原生调用，不进入扩展数据。 |
| 数字对象、滑块、依赖符号计算的表达式，如 `k`、`3+2`、`Floor(k)` | 原样交给 GeoGebra；不读取当前值，不把动态编号冻结为静态配方。 |
| 大于原生上限、值为安全整数的数字字面量，如 `3054`、`3054.0`、`3.054e3`，包括无歧义的外层括号 | 按本站已接入的编号查找，仅展开所选点。不存在、暂缓或不支持的编号给清楚的错误；不调用巨大原生 `If` 表。 |
| 负数、值非整数的小数、字符串等 | 默认保留原生行为；扩展只承诺正整数编号。具体词法先写边界测试。 |

词法条件必须在 **选择站点重载前** 执行。现有 `catalogId` 重载会接受 `number`/`unknown` 类型并在缺少 `literal` 时抛错；直接照搬 `GibertCurve` 会误拦截滑块及计算式。当前编译器在文件工具检查之后对 `TriangleCenter` 单独门控，并把合格数字字面量规范化为整数 ID；不能通过捕获任意 builder 错误再尝试原生命令。保留文件工具优先级、大小写及嵌套调用的既有规则。通过实际 GeoGebra 检查 `3053`、`3054`、`n`、`3054.0`、`(3054)`、未知大编号以及用户文件宏同名情形。

输出必须是单个动态的实仿射 `point`。编译时只选配方，几何量仍由 GeoGebra 根据 A/B/C 动态计算；不在 JS 里读取三角形当前坐标，不安装宏或回调。含扩展中心的保存、导出、重开必须保留原生依赖。复杂配方可能需要命名辅助对象，此时沿用 `bind()`、`compileStudioPlan`、回滚/撤销/清理机制；先实测是否真的需要 `requiresNamed`，不能因与高次曲线共用接口而一律强制 Medium/High。

## 3. 数据模型：优先存短定义，不能把 ETC 文字直接当程序

当前采用 **ETC 原文 + 受限提取规则 + 少量人工种子 + 生成的运行时索引**。原始网页留在被 Git 忽略的本地缓存，冗长坐标和条目旁的大量关系表都不进入网站包。人工主要维护解析规则、例外和抽样审计，不逐条录入或阅读数百个点。正式配方以短行存储；来源由页号及 `#Xn` 锚点定位，另在本地审计表保留匹配到的原句。未解决的点保持缺席，不造占位坐标；Git 管理规则、种子和生成数据。

初拟的有类型配方语言（例子是**候选形状，不是已经核实的入库定义**）：

| 类别 | 候选表示 | 取舍 |
| --- | --- | --- |
| 原生锚点/重用 | `N(id)` | 只限确有原生有限点的配置；大编号引用递归展开，不能留给原生 `TriangleCenter`。 |
| 仿射组合 | `M(p,q)`、`R(p,q)`、`C(p)`、`AC(p)`、`L(p,q,r,s)` | 中点、关于点反射、补/反补、短系数线性组合。优先选这类少奇异的定义；系数必须明确是仿射点组合还是齐次权重。 |
| 射影/共轭 | `J(p,q,r,s)`、`IG(p)`、`IT(p)`、`HC(p,q,r)`、`INV(...)` | 两线交点、等角/等截共轭、调和、反演等。先确认有唯一有限实输出；不要因公式短就跳过退化审查。 |
| ETC 特殊变换 | `CP(...)`、`CC(...)`、`CVP(...)`、`CVC(...)` 等 | crosspoint、crossconjugate、cevapoint、cevaconjugate 必须按 ETC 定义核对参数顺序与本站已有命令语义；逐类加入，不能只匹配名称。 |
| 紧凑坐标后备 | `B(f(a,b,c))` 或三线 `T(f)` 的受限表达式/小型算术电路 | 仅用于没有短构造、但公式可靠且可解析的点。周期置换生成另两坐标；三线需乘边长转重心。共享常见子式，不把长网页公式原样塞进客户端。 |
| 条件/复数/无穷远 | 显式 `deferred` 分类，必要时附候选定义的限制 | 不用虚假实点填空；仅当能在相应实数域给出正确单值点时再加入。 |

配方形成按编号引用的有向无环图；**不能假设引用编号总比目标小**。生成器从原生锚点及已验证种子出发，仅选择依赖已闭合的候选，最后再对完整输出作 DFS 校验，拒绝缺失引用或任意长度的环；运行时也保留环检测。候选按依赖深度、展开长度和操作类型排序，限制最大深度/长度。原生点是否在各种三角形上为有限实点仍须作批量域筛查；目前的图校验并不证明这一性质。既有 `IsogonalConjugate` 等工具可借用已验证的数学实现，但直接使用 `expression` 的原生命令不会被编译器再次展开，跨大编号引用需由专用 builder 递归解析。

### 紧凑性与加载策略

不建议把七万多条记录写成带重复键名的 JSON 对象，也不建议生成一个含所有中心的大型 TS `switch`。推荐先试验 **按 ETC 页/编号范围分块的紧凑配方**：操作码 + 变长整数参数，连续编号省略重复 ID；同构连续族用范围起点、长度、参数递推描述，个别例外单列。人工可读来源可用短行/范围声明，生成产物可用紧凑文本或二进制；重复子式用小型字典。只有坐标后备条目才保存受限公式。不要为了压缩而破坏编号到来源的可追溯性或引入复杂运行时解释器。

启动包仅带命令入口与极小的块目录；编号选择后加载所需块，完成依赖闭包再交给现有同步编译器。`commandPipeline` 已是异步的，但 `compileStudioCommand`/`compileStudioPlan` 是同步的，因此实施阶段必须明确设计「预加载依赖闭包 → 同步展开」接口和错误传播；嵌套调用、同一行多个中心、补全与撤销不能偶然同步请求数据。若试验发现整套压缩配方非常小，也可一次加载；必须用实测决定，不能假设动态分块必然更快。生成器可额外输出块间依赖索引，防止递归网络瀑布；块内索引用偏移表或紧凑有序编号，避免把所有稀疏项展开为大型 JS 对象。

空间预算先按实际语料测量：作者源文件大小、生成数据原始与 Brotli/gzip 传输大小、初始 JS 增量、首个/跨块查询加载量、解码后的堆占用。比较至少三种小样：紧凑文本、二进制变长整数、普通紧凑 JSON；记录配方操作数分布、范围族覆盖率、长公式占比。不能凭单点字符串长度估算最终包大小。目标是初始页面不加载整个中心库，且已选编号的构造与拖动开销主要由其依赖图决定，而非总记录数。

## 4. 数学域、退化与数值方案

- 先作一个小的原生基准：对 1–3053 在数个不等边、不共线三角形上批量取 `isDefined`、`getObjectType`、坐标与随点移动行为，粗筛有限/无穷远/条件点/异常。数值筛查只能形成候选，不能证明“实且有限”；复点或依三角形形状改变实性的点须单独核对 ETC 定义。
- 区分四种输出状态：一般位置有限实点；合法域内的条件实点；射影无穷远点；复点/非单值对象。普通 GeoGebra `point` 只承诺前两种的适用配置。若所选短构造经过无穷远或复中间点，即使最终点有限，也不能用普通仿射中点/原生交点串联；要改用齐次消元或另选定义，否则暂缓。
- 对一般位置的两个实有限点，仿射中点、反射、补/反补通常最适合批量化。交点需排除重合线与平行线；等角/等截共轭、反演、调和、Ceva/Cross 类需检查分母、边线、顶点及参数重合。很多重合仅在正三角形出现，但不得把这一经验当成全部变换的定理。
- 遵守[现有退化约定](implementation-plan.md#23-退化和连续性)：最终数学对象良定时尽量消掉中间可约 `0/0`；输出本来无穷远、复或不唯一时可以 undefined。为大规模接入，本工具允许在测度为零的特殊三角形上有少量非关键失败，但必须在每类配方的契约中说明；不以固定世界坐标 epsilon、随机扰动或当前快照掩盖问题。数值上极远的有限点与理论无穷远不能靠固定阈值硬判。
- 交线和有理坐标若采用齐次三元组，在最后一步才除以坐标和/第三分量；全零向量表示不定。任何符号化简必须核对约去的因子，避免把原本不良定的域扩大为错误点。对大量简单点仍优先用原生点运算，不能为了边界稳定而把所有符号坐标存下来。

## 5. 离线数据准备与人工维护流程（后续轮次）

1. 人工决定更新哪些 ETC 页面，低并发、限速地下载到被 Git 忽略的本地缓存；不在站点运行时抓取，也不定时同步。当前 `triangle_center_import.py fetch --parts ...` 是显式人工触发命令；只处理实际含条目的页面。
2. 以 HTML 的 `h3#Xn` 标题切条目，局部解析正文；仅识别**条目自己明确写出的**中点、反射、补/反补、两线交点和可表达的投影句式。重复的 `(i,j)` 关系表可提供多个候选。禁止从“lies on lines”、`X[i]` 线性组合或无关提及推断定义；含 `if/when/provided` 等条件的句子暂缓。对[前言指南](https://faculty.evansville.edu/ck6/encyclopedia/Guide_to_preambles_in_ETC.html)中的连续族，后续单独增加经验证的范围解析器。
3. 自动选择依赖闭合、无环且展开预算内的候选。现已允许中点、点/直线反射、补/反补、显式两线交点、正交投影和等角/等截共轭；优先仿射短构造，共轭链最多一层。参考 `native-unavailable.txt` 排除在两种代表形状中原生未定义的依赖；标题明确是无穷远点及相对于别的三角形的变换暂缓。无法解析的长坐标和未闭合候选留在队列，不猜测。生成审计表记录匹配原句；人工按页、操作、前言区块、依赖深度抽样审阅，并针对解析规则或区块异常修正规则/例外，无须逐点批准。
4. 生成千号段运行时分块；`check` 对照缓存来源重算，`verify` 无须缓存即可校验已生成数据的引用和环。人工比较 ETC 更正页与当前数据，受重编号影响的引用一并修正。不要建设 ETag、自动定时更新或独立数据版本数据库。

## 6. 实施批次与验收门槛

| 批次 | 工作 | 完成条件 |
| --- | --- | --- |
| A. 核心接口与小样 | 确认项目引擎的原生边界；实现分派谓词、轻量索引、一个配方 builder 和小规模手工样本。 | 低编号与动态编号完全走原生；大字面量只展开选中的已接入编号；文件工具优先；存档、拖动、撤销、重开成立。 |
| B. 低奇异性批量 | 自动解析明确的中点、反射、补/反补关系；按页和区块扩展，维护少量人工种子及规则例外。 | 所有记录通过源句式、引用闭包、无环和展开预算校验；按页/操作/深度分层抽样核对原文及真实引擎，统计包大小与加载开销。 |
| C. 射影与共轭族 | 分别处理线交、调和、反演、等角/等截、crosspoint/crossconjugate、cevapoint/cevaconjugate；按操作类建立数学公式与域约定。 | 每类先有少量独立样例及原生动态验收，再扩大批量；无穷远/复/重合依赖先排除或换齐次方案。 |
| D. 坐标后备与困难条目 | 只为没有合适短构造的点生成受限循环坐标/算术电路；余下特殊族逐项研究。 | 长式通过精确或高精度独立对照、编译预算与原生性能；不合格编号明确暂缓。 |

每批对**解析规则及操作类**作测试，并按页面、区块、操作、依赖深度和特殊域风险抽取少量代表点进行独立定义对照与真实引擎验收；不为每个点单独建立浏览器测试。抽样涵盖非特殊、钝角、镜像、顶点轮换、输入拖动和保存重开；高风险类型再测等腰、直角、正三角形及退化后恢复。用相对尺度残差，离线数值对照不替代原生引擎验收。记录各类操作的创建/拖动时间、表达式长度和辅助对象数。

## 7. 开工前需通过的小型实验

1. 用约 2–3 个相距较远的真实 ETC 段做**只读**格式审计，统计短构造/坐标后备/特殊或条件点的比例；别把整站页面数当作有效记录数。
2. 以至少数千条已审核候选作三种格式的打包和加载基准，决定是否采用二进制与块大小；测冷启动、一次查询、跨块深依赖及重复查询。
3. 对普通点、中点、交点、共轭、齐次有限化各取代表，测试匿名与命名执行的对象预算、拖动、退化和文件生命周期；据此决定哪类需要 High、哪类保持 Low。

以上实验用于决定实现路径。数据按**规则审核 + 分层抽测**批量接入，不逐条人工审核。覆盖率应按「实际存在条目中已支持的有限实点」与「暂缓原因」报告，不能把 ETC 导航区间、复点或无穷远点算成实现失败，也不能以缺省坐标冒充支持。

## 8. 初步执行记录与区块取样修正（2026-10-31）

- 已接入 3 千号段的 16 个点和 X(73001)，人工记录见[3 千号段配方](../data/triangle-centers/chunks/3.txt)、[73 千号段配方](../data/triangle-centers/chunks/73.txt)及[维护说明](../data/triangle-centers/README.md)。六种操作共 17 个点，仍只是刻意挑选的管线样本，不代表任一段或全 ETC 的覆盖率。
- `TriangleCenter` 的站点分派只识别超过 3053 且值为安全整数的数字字面量。小编号、数字对象、计算式等仍走原生；文件宏优先。编译前按千位编号动态加载配方，并递归预备非原生依赖；数据块校验成功后才加入内存索引。X(73001) → X(3109) → 原生点的依赖链检验了跨块加载。真实引擎的独立页面 `scripts/geogebra/browser/verification.html?page=centers` 已验证 17 个一般位置的有限点、拖动 C 更新、导出重开后继续更新。此验收尚未覆盖退化形状、批量性能或复杂嵌套。
- [ETC 前言指南](https://faculty.evansville.edu/ck6/encyclopedia/Guide_to_preambles_in_ETC.html)明确列出连续同类区块，例如 X(17227)–X(17400) 的低次多项式族、X(47629)–X(48640) 附近的系数族；[第 37 部分](https://faculty.evansville.edu/ck6/encyclopedia/ETCPart37.html)中 X(73000) 一带有连续中点/反射关系及非常长的重心坐标。单从某个连续区块抽样会严重偏向该类操作，尤其不能据此推算坐标后备的全站占比。
- X(73000)–X(73003) 连续以中点命名，但直接中点配方分别依赖 X(72948)–X(72951)，这些依赖尚未接入；X(73001) 的另一条反射关系只依赖 X(476) 与可短构造的 X(3109)，所以能先接入。**标题同类不等于可同时实现**；区块审计应记录依赖闭包与可替代构造，不只记录条目表面类型。
- 后续格式审计采用两级口径：先按页面及前言标明的连续族划分区块，记录每块的实际条目数、构造类、公式长度与特殊域；再在每块内抽前/中/后及例外条目。分别报告**区块数比例**与**按实际点数加权的比例**，并列出未解析/未审阅的份额。只有覆盖多个时代和不同类型的大段后才估计全站存储量；格式基准同时用高度重复族与零散复杂段，避免压缩率被单一族抬高。

## 9. 数据审计与格式决策
