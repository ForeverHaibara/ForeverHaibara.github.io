# 命名辅助对象扩展到几何类型：技术调查与实施计划

日期：2026-10-29。状态：**High 档与一个点型辅助工具试点已实现；其余类型和工具仍按本计划逐项验证**。现有实现见 [实施说明](named-intermediates-implementation.md)，原规划见 [历史规划](named-intermediates-plan.md)。

## 结论与边界

GeoGebra 的 auxiliary 是对象属性，并不限定数值类型。官方 [Algebra View 手册](https://geogebra.github.io/docs/manual/en/Algebra_View/)说明辅助对象默认不在代数视图展示，并可由用户打开“显示辅助对象”；[Apps API](https://geogebra.github.io/docs/reference/en/GeoGebra_Apps_API/)提供 `setAuxiliary`、`setVisible`、`setLabelVisible`。因此隐藏几何中间点、线、圆锥曲线等在界面机制上可行。它们仍是可由名称、API、原生输入及文件数据访问的构造对象；隐藏不是私有名字空间，也不能保证 GeoGebra 原生的所有工具忽略它们。CAS 侧栏不自动生成 CAS 输入行，仍须实机核对在 CAS 中显式引用的行为。

本站目前的 `collapseInternalHelpers` 按内部标签收缩节点，与对象类型无关；`useDependencyGraph` 将收缩后的图送给关系发现，所以经过可靠识别的内部几何对象原则上不会作为发现候选。然而 `GeoGebraConstructionSource.read()` 先枚举并读取**全部**对象、提取点坐标，然后才收缩图；大量几何辅助对象仍增加原生 API、解析、保存文件及原生重算成本。仅凭 `setVisible(false)` 无法达到“几乎不影响其他功能”。目标应明确为：对本站的用户语义功能零可见污染、对 GeoGebra 原生构造保留依赖、整页交互与文件成本在可接受预算内。

已有命名试验还发现，`ThirdIntersection`、`CircularPolarPoint`、`CayleyBacharachPoint` 的命名版本把点输出变成向量。这表明允许几何绑定不是简单扩大类型白名单：GeoGebra 对命名赋值、`Element(Zip(...),1)` 和点／向量算式的类型推断可能不同。几何辅助物化前，必须先证明最终对象类型、坐标、定义状态、动态更新和退化恢复一致。

## 实施前的原生探针

在一次性构造中分别创建自由点、依赖点、向量、直线、线段、圆锥曲线、隐式曲线及点列表作为辅助对象，全部设为 auxiliary、图形不可见、标签不可见。逐项记录 GeoGebra 版本及以下结果：

1. 默认 Algebra、显示辅助对象的 Algebra、CAS、图形区、对象选择与 `showAllObjects` 下是否出现或可选；用 `getAllObjectNames`、`getObjectType`、`getXML` 核对对象始终存在且 auxiliary 属性在 `.ggb` 导出重开后保留。
2. 修改输入、撤销／重做、删除正式输出、原生重命名／重定义辅助对象时，几何依赖、可见性、组清理与用户主动引用的保护是否正确。
3. 原生关系／证明命令、对象选择与交互工具是否把不可见辅助点或线纳入候选。本站只能控制自己的枚举，不能假定 auxiliary 会改变 GeoGebra 原生算法。
4. 对同一工具比较匿名与命名版本的 GeoGebra 原生类型、值、定义域、退化恢复、文件重开；记录创建、拖动帧、关系发现刷新、自动保存、文件大小和内存。包含输入点重合、曲线退化、未定义分支和无输出情形。

若显示辅助对象后几何对象可见，这是 GeoGebra 原生可检查性，应在 UI 说明中明确；不可承诺彻底隐藏。若原生关系功能受影响且无可控的过滤入口，则几何模式不能宣称与原生行为完全等价，需缩小适用工具或提供明确限制。

## 类型与包装命令架构

沿用 `bind()` 的单一公式源、匿名降低器和命名降低器；不为每个工具维护两套公式。将目前的 `BindValueKind = number | numberList | function` 扩成结构化的 `BindingValueType`：标量、函数、点、向量、线／射线／线段、圆锥曲线、隐式曲线、以及带**元素类型**的列表。每个绑定记录预期 GeoGebra 原生类、维度、是否可独立物化、所属作用域与定义域／分支约束。类型未知时保持匿名。

先生成中立的绑定依赖图，再以策略降低为：匿名；仅非几何命名；允许已验证的几何命名。重载策略继续集中在 `NAMED_OVERLOADS` 一类的表中，记录允许类型、节点／总对象预算、预期输出类与实测收益。只有类型安全且在当前作用域外合法的节点才能提升；`Zip`、`KeepIf`、`Sequence`、`Curve` 等局部变量不能靠字符串扫描随意提升。未来可采用**逐节点物化**，让几何节点保持匿名而数值节点命名，或反过来，但必须按依赖顺序生成，并在单次调用内复用共享绑定。不能证明独立求值与 `If` 分支惰性语义等价时，整个受影响子树回退匿名。

几何表达式需要按预期原生类型构造，不能统一包一层 `Point(...)` 或仅用坐标式，因为它们可能改变依赖、点／向量类型、路径约束和退化行为。把“类型保持”作为每种包装规则的契约：编译期声明预期类型，原生执行后读 `getObjectType` 与 XML 类核验；点、向量、圆锥曲线的特殊分类应分别处理。列表需核验元素类型与长度，不能只检查外层 `list`。正式输出也要核验原生类、定义状态及分支数；不符时清理本次新建对象并报告失败，不能悄悄接受类型变化。

执行计划保留有序 `helpers`、正式输出和组 ID，并增加每个 helper 的类型契约及来源绑定。执行器仍按依赖顺序创建、核验、设 auxiliary／图形／标签状态；新增几何对象须在呈现之前尽可能设为不可见，实测多行命令期间是否出现短暂闪烁。创建失败时只清理由本次调用新建且可验证的对象。输出重定义继续先走匿名路径，直到原子替换语义得到验证。

## 与其他子系统的隔离

- **统一身份识别**：不能仅凭 `ggbaux...` 前缀把任何对象当内部对象。内存中使用本次计划登记；导入后用组 ID、XML auxiliary 标记、原生类及依赖一致性重建。无法确认身份时保守保留并作为普通对象处理，防止用户同名对象被隐藏或误删。
- **构造与发现**：在构造源读取前先按可信内部清单过滤发现候选，避免先为每个辅助点取坐标；仍需获取足够定义信息建立依赖并收缩链。为用户语义图保留“正式输入→输出”的边，关系发现、依赖评分、证明导出统一消费这个投影。内部几何节点既不计点数，也不进入线、圆、三角形或角度候选。
- **事件、样式和交互**：内部几何 add/update/style 事件应批量处理，输出变化后触发一次发现刷新和保存。现有补全、样式控制、对象链接、选中状态与命令结果继续排除内部对象；图形隐藏不应被全局样式或“显示全部对象”逻辑意外重置。原生输入栏仍可引用它们，用户显式引用后生命周期必须保留整组。
- **生命周期与文件**：`verifiedHelpers` 当前只接受 numeric/list/function，几何类型扩展时要用允许类的精确集合、XML auxiliary 与登记共同核验。删除孤儿按组逆依赖序进行；用户重命名或改写内部对象时放弃自动删除。撤销、重做、导出重开与旧非几何文件都应保持原来的依赖与隐藏状态。
- **性能预算**：几何对象的原生重算、图形对象登记、关系源读取和 `.ggb` 大小可能高于数值对象。分别设置总节点数、几何节点数、最大列表长度与文件／刷新预算；以整页收益决定是否启用某重载，而非仅看命令创建耗时。

## 设置与兼容

把当前布尔偏好迁移为三级执行模式：`off`、`nonGeometric`、`verifiedGeometry`。旧 `false` 映射 `off`，旧 `true` 映射 `nonGeometric`；默认仍为 `off`。前端 Workspace settings 的 Custom tool performance 改为单选三档，并说明“包括几何辅助对象”仅针对已验证工具、可在 GeoGebra 显示辅助对象时查看、只影响新命令。关闭或降低模式不删除已有辅助对象。文件保存对象依赖，不保存或强制改变本机偏好。

## 分阶段验收

1. 完成上述原生探针与基准，先确定几何类型中哪些可安全隐藏和稳定保存；没有结果前不扩大生产白名单。
2. 引入结构化类型契约、策略表与可诊断的回退原因；保持默认匿名文本及现有非几何模式的结果不变。
3. 先选一个包含点绑定、收益可测的工具做端到端原型，优先调查 `QLQu3` 等现有候选；不能因工具名称而跳过同类工具筛选。点／向量语义问题解决后再扩至线、圆锥曲线及几何列表。
4. 打通可信身份、提前过滤、语义图收缩、事件与生命周期；比较关闭、非几何、含几何三种模式的发现结果和依赖图。以实际 Studio 全流程计时验收。
5. 补普通、退化、拖动、撤销、文件重开、用户引用及显示辅助对象的回归矩阵；按重载逐项启用。若某工具仅部分绑定安全，则采用逐节点物化或保持匿名，不强求两套实现。

发布门槛：默认与现有非几何模式零回归；开启几何模式后正式输出在原生类型、值、定义域和动态行为上等价；本站关系发现及证明候选不含内部几何；原生交互、撤销、保存和用户引用没有不可接受的副作用；整页性能收益足以抵消额外对象成本。不能满足的重载保持现有路径。
