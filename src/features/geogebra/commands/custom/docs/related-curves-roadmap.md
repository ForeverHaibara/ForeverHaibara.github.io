# 三角形高次曲线目录：接入计划

日期：2026-10-29。状态：**规划与原生实验，尚未实现目录命令、数据库、采集器或生成器**。目标来源为 [Bernard Gibert 的 Related Curves](http://bernard-gibert.fr/relatedcurves.html)，范围为经审阅确认次数大于 3 的曲线。本轮只新增本文和独立实验材料；本文提到的新路径、字段与接口均为下一阶段提案。

## 1. 建议采用的方案

1. 公开命令暂定 **`GibertCurve(A,B,C,id)` → 一个 `implicitCurve`**。一个目录入口，不注册 `Q012`、`Q039` 等几百个命令，也不先增加同义别名。
2. `id` 是**编译期目录选择器**，第一批以正整数字面量为主：`GibertCurve(A,B,C,12)`。不接受滑块、数值对象、任意算术表达式；不读取 `getValue(id)` 冻结选择。
3. 为目录中的带后缀条目预留同一个四参数接口：`GibertCurve(A,B,C,"Q…")`。字符串也只能是字面量，实际拼写来自目录清单，不能臆造后缀。数字入口的范围与字符串入口的首次交付范围在清单审计后冻结。
4. 外层 TypeScript 对规范 ID 做一次注册表查找，只为选中曲线生成原生表达式；**不把整个目录生成成 GeoGebra `If`、`Element` 列表或 `Sequence`**。ID 查找是静态的，A/B/C 的几何依赖始终动态保留。
5. 数据路线为 **源清单 → 原始证据 → 审阅过的数学数据库 → 确定性代码生成 → 分批原生验收**。运行网站不抓取 Gibert、不解析 HTML、不联网补公式。
6. 首批只交付少量已核实的代表曲线；按表达式复杂度和真实引擎性能分级。一次测通五次或六次曲线不代表整个目录可直接上线。

## 2. 与现有库的约定衔接

已读 [README](../README.md)、[原实施计划](implementation-plan.md)、[三次曲线后续计划](cubic-tools-roadmap.md)、[命名中间量设计](named-intermediates-implementation.md)，并核对 `types.ts`、`toolLibrary.ts`、`commandCompiler.ts`、`commandSyntax.ts`、`commandEnvironment.ts`、`commandPipeline.ts` 和相关 builder。

本次代码快照的 `library.json` 为 **0.2.0，162 个规范命令、25 个别名、187 个可调用名称**。README 与旧计划仍留有 0.1.0／137 个命令等历史表述。后续实施应以代码为准，并另行同步相关文档；本轮不顺带修改版本和历史记录。

| 现有规则 | 新目录应如何遵循 |
| --- | --- |
| `library.json` 是名称、英文描述、参数、返回类型的声明源；实现为 expression／compose／builder 三选一 | 增加一个目录命令和一个分发 builder；每条曲线是数据记录或内部生成实现，不成为公开 ToolDefinition。 |
| 文件工具／文件 callable > 站点重载 > 原生命令 | 文件中同名 `GibertCurve` 继续优先；嵌套、赋值、大小写、文件宏和错误处理都走现有编译管线。 |
| builder 只获得表达式、类型和卫生变量分配器，不获得引擎与实时数值 | ID 从字面量静态解析；边长、中心及坐标由原生表达式计算，禁止读取坐标快照生成固定曲线。 |
| 参数类型目前没有 text、目录 ID 或字面量约束；number 也会匹配滑块与算术式 | 不能只声明第四参数为 number 就宣称已限制。需增加静态参数约束及明确诊断；字符串扩展需同时审计类型推断、验证、补全、组合与环境读取。 |
| compose 用带类型的不透明 token 隔离调用方；locals 仅文本展开，不保证缓存 | ID 的静态常量信息必须穿过组合边界，或显式禁止目录选择器来自无法保留常量来源的 compose 参数；不能对随机 token 正则猜 ID。 |
| 表达式上限 500,000 字符，嵌套上限 64 | 这是失败保护，不是性能预算；在生成前另设更严格的逐曲线规模门槛。 |
| Low 默认匿名；Medium／High 按经过验证的重载白名单物化中间量 | 先比较短式、匿名数值系数、命名数值系数、原生重心后端。不能默认“命名一定更快”；如仅 High 可用，须显式说明，不静默启动已知会卡住的 Low 路径。 |
| 输出为原生对象，导出后无需站点代码、更新回调或宏 | 结果和必要辅助依赖均保存进 `.ggb`；A/B/C 移动、撤销、重开必须仍然正确。 |
| 独立几何输出可单独选择，内部辅助有标记与生命周期 | 通常只返回一条隐式曲线，不把系数列表或内部族当成用户输出。 |

`implicitCurve` 已识别原生 `ImplicitCurve`、`TriangleCurve`、`Cubic`，因此新命令本身不必新增曲线对象大类。但当前三次专用工具的系数提取／次数守卫仍只处理三次，不能因为新对象同属 implicitCurve 就宣称其 Hessian、第三交点等操作适用于高次。共轭曲线代码也有明确次数边界，不能自动扩大。

## 3. 命名与 ID 契约

### 为什么推荐 GibertCurve

| 候选 | 判断 |
| --- | --- |
| `GibertCurve` | 当前站点名称／别名和本地原生命令索引中未见冲突；直接表达所用编号来源，不承诺任意三角形曲线都能由此构造。推荐。 |
| `RelatedCurve` | 简短，但无法单独解释“related to 什么、哪个编号表”；可用但不优于来源明确的名称。 |
| `TriangleCurve` | 与原生同名，技术上可做 number 重载，但需要承担特殊方程作用域和未来兼容性责任。本阶段不建议占用。 |
| `TriangleQuartic`／`TriangleHigherCurve` | 前者不适用于五次以上；后者没有说明编号来源。 |

[原生 TriangleCurve](https://geogebra.github.io/docs/manual/en/commands/TriangleCurve/) 的第四参数是以 A、B、C 为重心变量的方程；输入点即使也叫 A、B、C，方程里的同名字母仍解释为重心变量，官方明确提示不能在其中直接以 `x(A)` 引用输入点。

重载并非必然冲突：本轮用**仅在实验内提供的 synthetic ToolDefinition** 验证，四参数 number 形式会选中站点重载，而 `(A-B)*(B-C)*(C-A)=0` 仍回落原生命令。但这不是全部兼容性证明：数值对象也会被选中，未知类型可能回落，新增字面量验证若放在错误位置会拦截原生合法方程；原生公式中的 A/B/C 也不同于普通调用作用域。若将来坚持此名称，先补原生完整方程／布尔对象、括号方括号、未知表达式、嵌套、文件工具、重定义、原生大小写与本地化回归，并区分“未匹配”和“匹配后校验失败”。采用独立名称可避免为这套目录额外承担该兼容接口。

### 拟冻结的行为

- `GibertCurve(A,B,C,12)` 对应**目录 Q012**，不按次数、数组位置、网页行号或抓取顺序编号。只接受正十进制整数字面量；可去掉语法上完整包围它的括号和两端空白。第一版拒绝 `12.0`、`1.2e1`、`6+6`、滑块 `n`、`floor(n)`；不尝试求值后判断整数。不得使用 JS `eval` 或宽松 `parseInt`。
- 数字 ID 查表得到规范记录；不设“1 到某最大值都支持”的假象。缺号、未收录、未审阅、暂缓和已禁用分别给出可操作的错误信息。
- 字符串形式如 `"Q012"` 可与数字 12 同义；带后缀／特殊编号必须使用清单认可的完整字符串。已找到资料含 `Q000H3`、`Q000aH3`、`Q035-A-B-C` 等记法，证明不能预设全部条目都是整数。最后一类也可能是网页对一组三条的合写，**实际原子 ID 必须查清才生成**。
- 若一个目录号代表多条不同曲线，数字调用应报出可选的完整 ID；不静默取第一条，也不改变本命令“一个输出”的承诺。另一种多输出族接口须单独设计，不能混在这一入口里。
- 不支持以滑块在几百个实现之间动态切换。用户换 ID 就重新执行命令／重定义输出；现有 `.ggb` 保存展开后的定义，不依赖注册表 ID 的后续解释。后续优化公式不会自动改写已有构造。
- `GibertCurve(A,B,C,id)` 公开层固定四参数。不是每条曲线都对任意顶点置换不变：A/B/C 顺序、循环协变、方向敏感和变体映射属于数据库元数据与测试契约。

实现时优先把“编译期目录字面量”建模为独立参数约束，而不是一个新的几何输出类型。可为 TypedExpression 增加经词法解析得到的常量来源元数据，数字仍属 number；若第一版支持文本 ID，则补齐 text 的现有类型链路。不得用 unknown 通配符直接吞掉任意第四实参，也不得只在页面提交按钮前做字符串替换，否则嵌套、compose 和文件工具优先级会失效。

内部拟为 `normalizeCatalogId → verifiedRegistry.get(id) → selectedRecipe → existing native execution`。注册表只含已批准记录；源文件可按 ID 区段组织。先测增加目录后 JS 包体、初始化时间，再决定是否需要静态分块；异步按需 import 会影响当前同步编译器契约，不能为“以后可能很大”先行重写编译器。

## 4. 来源调查与数据准备

本轮是有限资料调查，没有运行全站爬取。总目录直接访问发生超时／502，嵌入浏览器还报告证书信任错误；未绕过证书警告。部分曲线与论文内容通过网页搜索索引获得，因此目前**没有完整条目数、完整下载链接清单或“无统一下载”的确定结论**。

已确认的线索：

- [Downloads](https://bernard-gibert.fr/downloads.html) 有论文资源；这不等于存在全部高次曲线的 GeoGebra 文件合集。
- [Q106](https://bernard-gibert.fr/curves/q106.html)、[Q110](https://www.bernard-gibert.fr/curves/q110.html) 的页面明确提到方程过长，提供文本下载。采集范围须包含实际链接的文本资源，不能只抽取 HTML 正文；本轮未下载这些方程。
- [ETC—Related Curves 关联表](https://bernard-gibert.fr/Resources/Others_2.html) 的索引内容标注更新于 2026-09-23、采样至 Q201、覆盖 73048 个 ETC 点。它能提供关联候选，但“采样通过”不是符号恒等证明，也不保证覆盖更晚条目、全部变体或所有特征点。它不是曲线方程数据库。
- 页面可能采用普通文字、上下标、循环求和、乘积、图片、外链 TXT、PDF 或关联曲线的变换定义。必须保留原文证据并分类人工复核，不能把一个通用正则解析器的产出直接发版。

### 数据准备阶段的具体交付

1. **先审计可批量利用的已有资源**：目录、Downloads、每页的 `.ggb`／`.ggt`／其他动态几何文件／文本／压缩包链接及覆盖范围、版本、格式和再分发条件。若已有完整且可核验的结构化包，优先使用并逐项比对；图片或一组固定三角形坐标的绘图文件不能替代动态方程。
2. **目录清单**：从真实目录链接收集 ID、原始拼写、名称、URL、标称次数、族／变体关系和资源链接；保留缺号、重复、转移和旧别名。统计目录项数、原子曲线数、可用公式数分别是多少，不把三者混为一谈。
3. **可追溯原始证据**：记录请求 URL、最终 URL、抓取时间、编码、HTTP 状态、ETag／Last-Modified、SHA-256、页面内来源定位。原始下载内容与人工提炼公式分离；根据授权范围决定原文是否入库，数学数据库始终保留出处。
4. **小样本格式审计**：先处理 10–15 条，覆盖短循环式、TXT、PDF、图片、仅几何定义、族变体、次数较高、无可用 ETC 点。估计自动化率和人工成本后才扩量。
5. **批量采集**：限来源域名及明确链接资源、单并发、默认每请求至少 5 秒并加抖动；先读 robots 与使用说明。设置超时、最大资源尺寸、续传检查点和缓存；支持条件请求。429／503 遵循 Retry-After，失败最多两次指数退避，不持续重试证书错误或强行绕限制。一次完整快照后离线处理；后续只更新变化资源。具体速率依据网站反馈调低。
6. **人工审阅队列**：保留 `missingEquation`、`imageOnly`、`ambiguousNotation`、`unverifiedDegree`、`needsDerivation`、`slow` 等阻塞原因。抓不到、解析不了或验证未通过的条目仍保留目录元数据，但不进入运行时生成表。

建议将未来可维护数据放在 `custom/data/related-curves/`，原始采集工作区和脚本放在 `scripts/geogebra/related-curves/`，生成实现放在 `custom/generated/related-curves/`。这是职责划分提案，本轮不创建空数据库或伪样本冒充正式记录。

## 5. 数据库与公式规范

建议采用可校验、可 review 的 JSON／JSONL 源文件，而非先引入运行时 SQL。数据库是数学定义的单一真值，生成的 TS 可丢弃重建，禁止在生成文件中人工修公式。

| 字段组 | 必要内容 |
| --- | --- |
| 身份 | schemaVersion、规范字符串 ID、numericShortcut（可空）、来源原始 ID、英文名、族／父项／变体映射。 |
| 来源 | 页面、论文／方程文件 URL，证据位置、快照 hash、更新时间、审阅人／日期、使用条件。 |
| 数学 | 标称射影次数、归一化后验证次数、barycentric／trilinear／Cartesian 坐标系、齐次性、域条件、顶点顺序、实分支／代数闭包语义。 |
| 公式 | 审阅后的受限 AST／稀疏单项式、系数依赖 DAG；只允许确定的符号、运算与有限循环，不允许任意可执行 JS 或未经检查的 GeoGebra 字符串。 |
| 分量 | 已知因子、重数、分母及其排除集合；清分母／消去产生的附加分量及去除依据。 |
| 测试 | 已知点和来源、有限／实数／适用条件，奇点／切线／几何刻画、负例、对称性、特殊三角形预期、独立验证方式。 |
| 工程 | reviewStatus、支持的后端与档位、展开长度、单项式数／节点数、实机性能、引擎版本、禁用原因。 |

数学约定：

- 固定 `a=|BC|, b=|CA|, c=|AB|`；AST 中重心变量使用 `u,v,w`，与仿射 `x,y`、顶点 A/B/C、目录选择器 id 分离。`S_A` 等简写必须在记录中显式定义，不能只依赖页面习惯。
- 三线坐标 `(α:β:γ)` 转重心为 `(aα:bβ:cγ)`；方程转换方向则需将三线变量替成 `(u/a,v/b,w/c)`，再经过有依据的清分母。不能把点的转换规则直接照搬为方程替换。
- 循环和严格表示 `(a,b,c;u,v,w) → (b,c,a;v,w,u) → (c,a,b;w,u,v)`。对称和、交错和、乘积和 `: :` 三个坐标的省略规则分别处理；根号、三角函数、面积符号和旁心的符号分支均须注明。
- 齐次方程 `F(u,v,w)=0` 采用现有有向二倍面积的线性重心变量代入，从而不除三角形面积；非齐次重心式先明确 `u+v+w=1`，按总次数齐次化。不能无条件用未归一化重心变量替换非齐次式。
- 运行中保留输入 A/B/C 依赖。静态符号化简、公共因子提取和稀疏系数生成可以离线做；几何系数必须交给 GeoGebra 动态计算。
- 射影分量、有限实轨迹与消元后的代数闭包可能不同。只删去已证明的赘因子，不能因为图中不明显就删除分量。圆点、无穷远分量和重复因子应保留元数据。
- 重合／共线三角形须为 undefined；恒零多项式不能当成整平面或有效曲线。正三角形等特化可能降次或分解，要按逐曲线数学定义决定是否保留，不能统一“低于标称次数就拒绝”。已有实测表明 `ImplicitCurve(0)` 的 defined 标志不足以辨别恒零。

生成流程：受限 AST 校验 → 齐次性／次数／分量审计 → 系数依赖化简 → 候选后端 → 原生测试 → 已批准注册表。生成器应确定性排序，记录输入数据库 hash 与生成器版本，支持 `--check`，对数据库变更给出新增／删除／次数／支持状态差异。构建时和运行时均不依赖源网站在线。

## 6. 作图后端与性能策略

优先比较以下路径，按曲线选择；不建立“次数越高一定越慢”的单一规则。

1. **短重心式直接代入 `ImplicitCurve`**：最容易保持现有卫生变量和无命名依赖约定，适合基线。但符号重复和引擎展开可能昂贵。
2. **离线展开为稀疏笛卡尔系数、原生动态计算系数**：把与动点无关的计算从多项式变量中移出；比较因式式／Horner／稀疏式，不能仅凭字符数判断速度。
3. **匿名绑定共享数值系数**：沿用 bind；先测再采用。作用域中携带隐式对象可能改变原生类型或性能，不自动推广。
4. **原生 `TriangleCurve` 后端**：数学上直接接受重心方程，作为内部 native template 时不等于公开命令也叫 TriangleCurve。必须先解决 A/B/C 变量遮蔽，以及数值系数如何安全绑定／物化。
5. **命名数值系数和已证明更简洁的几何构造**：对经过实机验证的记录加入对应档位白名单，复用现有辅助标记／回滚／撤销／保存／孤儿清理；不要逐曲线复制执行器。几何捷径的分支、退化与额外分量也必须等价。

本轮实验的记录与复现入口见 [性能实验](benchmarks/related-curves-probe.md)。Q012 的直接隐式路径单次更新约 703 ms，原生重心后端约 154 ms；Q039 六次式两条路径分别约 1308／809 ms。两条曲线都能创建、动态更新并导出重开，但尚不能视为流畅拖动或可直接批量接入的依据。最终数字与原始数据在实验记录中集中维护。

下一阶段拟用的发布门槛（工程目标，不是本轮已达成指标）：普通测试机上创建中位数 ≤1 秒、更新 p95 ≤100 ms 为交互优先；更新 100–500 ms 标记需优化；超过 500 ms 不默认批量上线。创建超过 3 秒须单独说明与隔离评估，超过 10 秒先列为暂缓。高次个别例外可在用户明确选择后提供，但不能只凭“没有崩溃”判定可用。门槛需结合本项目现有慢工具、真实设备和完整页面复测后冻结。

测量记录必须含引擎实际版本、设备／浏览器、固定画布与坐标范围、是否前台、warmup、创建与更新原始样本、中位数与 p95、对象数、表达式长度、文件大小。分别测 API 完成和绘制帧等待；两次 requestAnimationFrame 只是绘制机会，不是严格像素完成／输入延迟证明。再测平移、缩放、连续拖动、5／10 条同时存在、关系刷新和自动保存成本，不能把独立 harness 数据等同整页体验。

实验应运行在可关闭的独立标签页／进程，逐条启动，外部看门狗记录阶段并在超时后关闭实验。与引擎同一主线程中的 `Promise.race`／定时器不能中断卡住的同步求值；不得把它写成“安全超时”。本轮实验没有自动进程终止机制，只使用人工可控的独立页面。

## 7. 正确性与特征点测试

[官方 TriangleCenter 文档](https://geogebra.github.io/docs/manual/en/commands/TriangleCenter/) 标注 `n < 3054`，不能假定可用到 73048。本轮实际引擎 5.4.920.0 中，3053 已定义，3054／3585／5456／73048 的命令被接受但点为 undefined；没有穷举低编号。后续仍须按实际引擎探测、保存结果，不能把“命令被接受”当作“点已定义”。

测试层次：

1. **数据结构与符号检查**：唯一 ID／规范映射、无悬空变体、允许符号、次数／齐次性、循环展开、分母条件、非零式、来源和审阅状态完整。用精确有理数与独立符号代数检查一般样本，不把生产生成器自己产生的表达式再次代入当独立证明。
2. **已知点关联**：优先选原生可定义的多个独立 ETC 点，跨至少三个一般斜三角形，并包括平移／旋转／镜像／尺度变化。先核对点的 defined、finite、real，再测归一化残差。顶点和明显因子上的点常自动满足方程，不足以排除错曲线；同时要有非曲线点、全零检查，以及足够多独立取值／系数比例检查。
3. **超出原生编号的点**：不为此提前实现整个 ETC。按需要收录少量有出处的显式重心／三线公式，或独立几何构造，并标记测试数据的适用域；不得硬编码某个三角形上的笛卡尔坐标冒充动态中心。
4. **没有合适已知点的曲线**：以独立几何刻画、与已验证曲线的变换关系、因子与次数、参数化样本或导数性质验证。采样点属于测试，不能转为生产输出的拟合点。资料不足可暂缓，不编造测试中心。
5. **特殊配置**：一般锐角／钝角／直角、等腰、正三角形、近共线、重复点、镜像；分别检查零式、降次、分量合并、奇点重数、离开退化后的恢复。对点多重性用导数核对，不只测 F(P)=0。
6. **原生工程验收**：输出 XML 类、动态定义、独立对象数、各性能档位、输入标签遮蔽、嵌套调用、文件宏优先、撤销重做、结果重命名／重定义／删除、导出重开、辅助清理与依赖图。生产代码不注册坐标更新回调。

归一化残差优先使用单项式绝对值贡献和等尺度分母，避免系数乘常数改变容差；接近零梯度、远离原点或极大尺度需额外策略。本轮探索 harness 仅用固定离曲线网格的量级作归一化，足以发现明显失败，**不能替代正式数据库验收的残差规范**。
