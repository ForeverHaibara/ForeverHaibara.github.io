# 自定义工具的命名非几何中间量：实施规划

日期：2026-10-29。状态：**规划；本轮不修改功能代码**。实测依据见 [命名中间量性能实验](benchmarks/named-intermediates-performance.md)。

## 目标与边界

在工作区设置中增加“允许自定义工具创建非几何中间量”的开关。默认关闭，继续使用现有匿名 `Element(Zip(...),1)` 路径。开启后，只对经过审核且实测有收益的工具调用生成命名辅助对象；其他工具仍走现有路径。设置只影响**以后执行**的命令，不能改变已存在对象的 GeoGebra 定义。原生输入栏、文件自带工具、`!API` 命令和导入文件不经过这项优化。

首版允许的辅助值限定为数值、只含数值的列表，以及经单独验证的多变量数值函数。列表的 GeoGebra 对象类型是 `list` 并不足以证明元素非几何；编译期必须有元素类型信息，运行后再核验对象类型。点、向量、直线、圆锥曲线、隐式曲线、含几何元素的列表和未知类型不得物化。特别是 `QLQu3` 当前有点值绑定，不能直接机械拆出全部中间量。

本阶段不使用 CAS 变量。它们与工作区对象在依赖、重算、保存和可见性上的语义不同，现有实测也没有覆盖 CAS。编译计划预留后端字段，待独立验证后再考虑 CAS。

## 现状与会受影响的路径

- `algebra/homogeneous.ts` 的 `bind(values, allocate, body)` 直接生成匿名 `Element(Zip(...),1)` 字符串。`ExpressionBuilder` 返回字符串或 `BuiltExpression`；`commandCompiler.ts` 返回单个展开字符串。
- `commandPipeline.ts` 逐条编译并调用 `engine.executeCommand`；`GeoGebraCommandBar` 只接收最终 `CommandResult`。多语句提交本来不是原子事务，前一语句可能在后一语句失败时保留。
- `useGeoGebraStudio` 将 `StudioSettings` 放在本地存储；`.ggb` 保存的是 GeoGebra 构造。已保存对象始终保留创建时的原生依赖式，不会随工具代码或开关变化而重编译。
- `GeoGebraConstructionSource`、对象补全和 `readCommandEnvironment` 都从 `getAllObjectNames` 枚举对象。当前分析图会为所有对象建节点；关系发现虽然主要观察几何坐标，依赖距离、证明问题导出和图 UI 仍会受额外节点影响。
- `PreferenceController` 在 `add` 事件上为新对象排队应用样式。一次创建几十个辅助对象会触发大量事件和分析刷新；原生性能实验没有计入这些页面成本。

## 核心架构：一套公式，两种降低方式

**不要维护两份数学公式，也不要在最终展开字符串上靠正则替换 `Element/Zip`。** 基准脚本的字符串拆解只是实验工具，不适合作为生产编译器：任意 `Zip`、`KeepIf`、`Sequence` 等有局部变量作用域，贸然提升其内部绑定会产生捕获或错误依赖。

建议在表达式生成层引入一个轻量的“绑定计划”表示，只结构化 `bind`，不重写整个 GeoGebra 语法。每个绑定节点记录：唯一 ID、顺序、值表达式、值类型／列表元素类型、局部变量、结果表达式、作用域和来源工具重载。普通原生命令片段仍是原样字符串。所有工具继续使用同一套代数生成函数，最后由两个降低器处理：

1. **匿名降低器**生成当前形式的 `Element(Zip(...),1)`。现有 `compileStudioCommand` 的字符串接口可作为兼容包装，默认输出应逐字或语义等价于当前实现。
2. **命名降低器**把合格节点拓扑排序，输出 `helper=expression` 的前置步骤及最终结果步骤。它只物化通过类型、作用域、成本和工具策略检查的节点；其余节点仍由匿名降低器局部展开。因此一个工具可以混用两种绑定方式。

计划对象建议包含 `prelude`、`outputs`、`expectedTypes`、`internalLabels`、原始命令和可诊断的回退理由。编译与执行分离：编译阶段不调用 GeoGebra、不读取输入数值，也不创建对象；执行器只消费已验证的计划。保留现有重载选择、文件工具优先级、组合循环检测、展开长度限制和多输出编号规则。

初版可以只将已选工具的绑定接入该结构；未接入的 builder 不需要改动。以后迁移更多工具时，优先把绑定声明移到共用生成原语中，而不是为每个工具写“快速版”公式。工具选择应放在**重载／builder 策略元数据**中，别按输入的命令名硬编码：别名共享重载，`Conic` 的不同签名却可能有完全不同的成本。策略可表达 `anonymous`、`eligible`、允许的辅助类型及可选上限；实际采用命名还要通过编译期安全检查。

### 安全提升规则

- 只有证明不引用局部迭代变量的绑定才能移到全局工作区。对 `Zip`、`KeepIf`、`Sequence`、`Curve` 等先采用保守拒绝；不能证明时保留匿名路径。首批样本不需要跨这些作用域提升。
- 函数声明头、字符串、注释、用户自定义函数和文件工具的名字空间继续由现有词法编译器处理。绑定 ID 与最终标签分离，避免把 `v1` 之类的局部名字误当成用户对象。
- 同一绑定被多个分支复用时，在调用内只建一次；跨不同用户调用不共享辅助对象。最终多输出必须各自保持独立原生对象，同时共享本次调用的合格标量依赖。
- `If` 的未采用分支、退化输入和未定义值可能改变 GeoGebra 的惰性求值行为。任何有副作用或在分支外求值会使定义域变窄的绑定均不能提前物化；对这些情况回退匿名。逐工具用退化测试证明等价，不能只凭普通位置的数值相等。
- 设置辅助对象数量和总表达式长度预算。超预算或类型不明时回退匿名，并记录可调试原因；不能在用户不知情时建几何辅助对象。

## 首批工具与筛选

| 对象 | 初步策略 | 理由／前置核验 |
|---|---|---|
| `Conic` 五条直线 | 首批命名；只物化数值 | 实测 36 个数值辅助对象，创建和更新均大幅改善。需覆盖直线、射线、线段的所有合法组合与退化分支。 |
| `Pretangential(F,A,i)` | 首批候选；允许数值、数值列表和多变量数值函数 | 第一分支实测明显改善。函数辅助对象必须隐藏且不进入几何发现；另外三个分支及无编号的四输出形式仍需验证。 |
| `QACu1Inv` | 保留匿名 | 实测没有稳定收益；额外 8 个对象不合算。 |
| `QLQu3` | 延后 | 基线求值会卡死，尚无可靠收益数字；内部点绑定不符合非几何限制。先拆分可安全物化的数值段并做限时基准。 |
| 其他工具 | 默认保留原状，逐个按数据加入 | 以创建、拖动、页面刷新总耗时和对象数量决定，不按表达式长度或 `Zip` 数量猜测。 |

切换设置不保证“所有工具都更快”；界面说明应明确是**对受支持的复杂工具使用隐藏的非几何辅助对象**。维护一份受支持重载清单和基准记录，新增候选需附等价与性能证据。

## 设置、可见性与名字空间

开关归入 Workspace settings 的 Behavior 类，作为本地执行偏好加入 `StudioSettings`，默认 `false`。读取旧本地数据时明确按布尔值归一化，避免畸形数据或字符串误开。开关随页面重载保留；导入、导出 `.ggb` 不应隐式改变当前偏好。打开开关不会批量改写现有构造；关闭后旧辅助对象仍是既有对象的依赖，不能删除。

命名辅助对象使用高熵调用组 ID、内部前缀及序号，并在执行前以现有标签集合检查碰撞；不复用 `v1`，不覆盖任何用户标签。计划中的 `internalLabels` 是用户不可见的实现细节；`CommandResult.labels`、历史和成功提示只报告正式输出。执行后核验标签、类型、依赖和数量。通过 GeoGebra 的 `setAuxiliary`、`setVisible(false)` 和标签可见性设置尽量隐藏；必须实测 Algebra、CAS、文件重开和“显示所有对象”下的行为。不能假定 `setVisible(false)` 会从代数栏移除对象。即使用户通过原生 GeoGebra 控件显式查看辅助对象，也不能把它们误报为正式工具输出。

内部对象识别不能仅靠前缀：应结合本次计划登记、GeoGebra auxiliary 标记、预期类型及组 ID。实验中函数辅助对象的原生类型字符串是 `multivariablefunction`，而现有 `normalizeGeometryType` 只显式识别 `functionnvar`；类型核验需要覆盖这两种实际返回值。导入 `.ggb` 后需要从文件中可携带的信息重建识别结果，不能只依赖内存或 IndexedDB；否则分享文件后完成、样式、分析与清理都会失效。输出重命名时组 ID 不变，依据实际依赖追踪所有权。用户若主动重命名或改写内部对象，不能在清理时误删其修改；这项交互需要专门测试和明确行为。

## 执行、失败与对象生命周期

先在纯编译阶段完成重载、类型、作用域、预算和命名检查，再提交 GeoGebra。执行器按依赖顺序创建辅助对象和正式输出，创建时登记计划中的标签；一旦发生部分失败，只清理由本次调用新建且仍符合登记信息的对象，绝不能删除碰撞到的用户对象。已有正式输出的重定义比新建复杂，首版建议回退匿名路径，等验证原子替换后再支持命名重定义。多语句输入保持现有“前句成功、后句失败时前句保留”的语义；单个命名工具调用内部则应尽量做到失败后无残留。

撤销／重做必须把一次工具调用视作一个用户动作。先实测一次多行原生命令和 `setUndoPoint` 的实际历史行为，再选择分组方式；不能假定 `asyncEvalCommandGetLabels` 自动给出单个撤销帧，也不能在失败时盲目调用 `undo()`，以免撤销用户先前操作。若无法稳定做到一次撤销同时恢复输出与全部辅助对象，则这是首版发布阻断项。

删除输出后，辅助对象可能成为孤儿；输入删除可能使输出与部分辅助对象一同消失。需要有组级生命周期协调器，订阅 add/remove/rename/clear/undo/redo，待事件突发结束后核对**实际依赖**，只清理无任何正式或用户对象引用的孤儿，且不能破坏撤销后恢复。导入、草稿恢复、重置和外部原生编辑后都要重建或核对组状态。清理应有幂等性，并避免对用户手工引用的辅助标签执行误删。若原生撤销模型不能安全支持自动垃圾回收，先选择保守保留并显式暴露诊断，而不是进行不可逆的猜测性删除；发布前仍需解决孤儿积累问题。

`.ggb` 文件应包含完整的原生辅助依赖，使离开本站也能重算；本地设置只决定未来命令采用哪条路径。导出重开、草稿自动保存、跨浏览器导入和旧文件兼容都要验证，不给文件加只在本站运行的 JavaScript 更新回调。

## 与页面其他系统的隔离

- **构造环境与补全**：内部标签仍要进入占用名称集合，避免覆盖；正常补全列表不展示它们。`readCommandEnvironment` 不应为每次新命令逐个读取全部辅助对象的定义／类型；显式输入内部标签时可选择按需解析或提示其为内部对象。文件工具优先级维持不变。
- **样式**：`PreferenceController` 不给辅助对象套用用户几何样式，也不把其属性写入 `managedStyles`。创建计划应在首个 add 事件前注册，以免样式控制器抢先处理。
- **分析与发现**：构造源可读完整原生依赖，但提供统一的“用户语义图”投影，将内部节点收缩为正式输入到输出的依赖边。关系发现、依赖距离评分、证明问题导出和默认依赖图都使用该投影；不能只是按 `objectType !== point` 排除，因为现有发现和证明路径也消费非点节点。收缩后一个工具调用不应因 36／93 个内部节点被计为几十步。显示全部对象的诊断视图可以单独选择是否展示内部节点。
- **事件与性能**：对本站发起的组创建／清理做批处理或事务标记，在完成后触发一次合理的分析刷新与草稿保存；保留原生编辑、拖动、撤销／重做事件。还需测拖动时 93 个数值更新是否造成分析重建队列和 UI 卡顿。
- **选择与可访问性**：对象链接、快速样式、状态文字、键盘补全只操作正式输出。内部对象不应因重开文件而突然进入这些列表。

## 建议实施顺序与验收门槛

1. **补原生语义探针**：确认辅助标记、代数栏可见性、多行命令撤销帧、删除后依赖行为、导出重开的标签与类型。记录 GeoGebra 版本及不同视图状态。若撤销或可见性无法满足用户预期，先调整方案，不进入大规模迁移。
2. **实现编译计划与匿名降低器**：现有工具的默认展开回归通过，文件工具和原生命令路径完全不变。增加作用域、类型及回退理由的单元测试；对嵌套 `Zip` 和未知列表类型明确回退。
3. **接入受控命名执行器及设置**：先只支持新建、单输出、类型可证明的调用。测试碰撞、部分失败、撤销、导入和关闭开关后旧对象持续更新。再扩展多输出和重定义。
4. **打通内部对象生命周期及语义图**：对删除、重命名、撤销、文件恢复、用户手工引用做端到端测试；比较开关开／关时几何关系、依赖评分、证明导出和补全结果。
5. **逐工具迁移**：先五切线 `Conic`，再 `Pretangential` 单分支和四输出；每一步比较普通、退化、动态拖动和导出重开。`QLQu3` 另做限时分段实验后再决定，`QACu1Inv` 暂不迁移。
6. **整页性能验收与文档更新**：在实际 Studio 中记录命令提交到可交互、拖动帧、分析刷新、自动保存、文件大小和内存。与关闭开关比较；不能只用原生 API 的 1.2／13 ms 更新数字宣称用户体验同幅改善。编译期超预算或不合格时回退匿名；原生执行失败时清理本次新建辅助对象并报告错误，不盲目重试。更新目前宣称“无命名中间对象”的 `README.md` 等说明，并公布支持的工具重载清单。

首版完成的判据：默认关闭行为无回归；开启后受支持工具的结果、退化恢复和文件重开与现状等价；仅允许的非几何辅助类型进入工作区；补全、样式、发现、证明和用户状态不出现内部标签；一次调用可正确撤销／重做；失败及删除后无不可控残留；整页实测仍有明确收益。
