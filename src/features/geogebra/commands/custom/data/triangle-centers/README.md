# Triangle center recipe data

The ten `chunks/*.txt` files contain 7511 defined centers (2026-10-31), including 239 ideal points represented by direction. They are generated from 17 reviewed entries in `seeds.txt` and 7494 automatically extracted constructions from [ETC Parts 3](https://faculty.evansville.edu/ck6/encyclopedia/ETCPart3.html), [4](https://faculty.evansville.edu/ck6/encyclopedia/ETCPart4.html), [5](https://faculty.evansville.edu/ck6/encyclopedia/ETCPart5.html), and [37](https://faculty.evansville.edu/ck6/encyclopedia/ETCPart37.html). Git tracks the compact generated data and extraction rules. ETC pages are manually downloaded to `.cache/triangle-centers/`, which Git ignores; no runtime or scheduled synchronization occurs.

Each row is `id operation references...`. `M p q` means midpoint; `R p q` reflects X(p) in X(q); `C p` and `A p` are complement and anticomplement. `I p q` represents an ideal point by the direction of the finite line X(p)X(q). `J p q r s` intersects two lines; either line may contain one ideal endpoint, rendered as a parallel through its finite endpoint. `P p q r` projects X(p) onto line X(q)X(r); `L p q r` reflects X(p) across line X(q)X(r). `G p` and `T p` are isogonal and isotomic conjugates of X(p); an ideal input uses homogeneous barycentrics. The parser accepts explicit relations within the target X(n) entry, including equivalent-pair lists, wrapped intersections, symbolic `∩` intersections, and line lists that share a heading with curve incidences. Listed pairs may use braces, parentheses, or a dot typo between IDs; an isolated damaged numeric token is skipped. It reads up to ten eligible listed lines and proposes pairs of lines with disjoint endpoints. An explicit intersection is preferred over an incidence-only pair when its dependencies become available. Barycentric expressions are not parsed. Conditions and transformations relative to a triangle other than ABC are excluded.

Run from the repository root with Python 3 and `beautifulsoup4`:

```sh
python scripts/geogebra/tools/triangle_center_import.py fetch --parts 1 2 3 4 5 37
python scripts/geogebra/tools/triangle_center_import.py native
python scripts/geogebra/tools/triangle_center_import.py build
python scripts/geogebra/tools/triangle_center_import.py check
python scripts/geogebra/tools/triangle_center_import.py verify
```

Before `native`, `build`, or `check`, run `/scripts/geogebra/browser/verification.html?page=center-anchors` against the local site, download its native coordinate sample, and copy it to `.cache/triangle-centers/native-atlas.json`. This ignored build-time sample covers two fixed triangle shapes and is never shipped to the app. Update `native-unavailable.txt` from the same screen when the GeoGebra engine changes. The manually cached ETC Parts 1 and 2 feed `native`, which regenerates `native-directions.txt` from the target's own `(parallel)` or infinity-line incidence lists. This is an explicit maintenance action, not automatic ETC synchronization.

`fetch` is the manual page update step. `build` uses cached HTML and the build-time coordinate sample, writes compact chunks, and writes a local `selected.tsv` audit table with source sentences. `check` regenerates from the cache and compares with Git data. `verify` needs neither cached HTML nor the coordinate sample; it checks all chunk IDs, dependencies, directed cycles, ideal/finite input types, and exclusions. A candidate enters only when its dependencies are native or already constructible; forward numeric references are allowed. Selection prefers affine constructions over line intersections and conjugates, caps each dependency path at one conjugation, and limits estimated expression growth. On both sample triangles, candidate direction lines must be nonzero, intersections finite, and an incidence-only pair must agree with a third independent listed line when available. Conjugates must be finite on both shapes. After graph closure, the builder revisits earlier intersections when a safer or explicitly stated definition has become available, then rechecks the final lines and directions. Unrepairable candidates and their dependent recipes are deferred. The full graph has maximum depth 6; the 7511 rows occupy 142,752 bytes before compression.

`native-unavailable.txt` records 229 native IDs that GeoGebra returned as undefined on at least one of the acute and obtuse representative triangles. Of these, 191 have a usable ideal direction from cached ETC Parts 1 and 2 and are listed in `native-directions.txt`. X(1912) is marked ideal but its two available native lines disagree on the samples, so it remains excluded. The other 37 unavailable IDs are not assumed ideal. `deferred-centers.txt` excludes X(72904), whose currently closed dependencies yield no consistent line pair. X(72060), previously excluded because its barycentric sum is zero, now has an `I` direction recipe. The build-time numeric graph checks every selected finite point and ideal direction on both shapes. A direct `TriangleCenter(...,idealId)` returns an undefined GeoGebra point because the engine has no drawable point at infinity; its direction remains available to dependent finite recipes. The earlier 35-point real-engine smoke test remains available; this batch used rule tests and the numeric graph screen. These samples do not prove behavior on every special triangle.
