# Triangle center recipe data

The ten `chunks/*.txt` files contain 7999 defined centers (2026-11-01), including 239 ideal points represented by direction. They are generated from 19 reviewed entries in `seeds.txt` and 7980 automatically extracted constructions from [ETC Parts 3](https://faculty.evansville.edu/ck6/encyclopedia/ETCPart3.html), [4](https://faculty.evansville.edu/ck6/encyclopedia/ETCPart4.html), [5](https://faculty.evansville.edu/ck6/encyclopedia/ETCPart5.html), and [37](https://faculty.evansville.edu/ck6/encyclopedia/ETCPart37.html). Git tracks the compact generated data and extraction rules. ETC pages are manually downloaded to `.cache/triangle-centers/`, which Git ignores; no runtime or scheduled synchronization occurs.

Each row is `id operation references...`. `M p q` means midpoint; `R p q` reflects X(p) in X(q); `C p` and `A p` are complement and anticomplement. `I p q` represents an ideal point by the direction of the finite line X(p)X(q). `J p q r s` intersects two lines; either line may contain one ideal endpoint, rendered as a parallel through its finite endpoint. `P p q r` projects X(p) onto line X(q)X(r); `L p q r` reflects X(p) across line X(q)X(r). `G p` and `T p` are isogonal and isotomic conjugates of X(p); an ideal input uses homogeneous barycentrics. `V p` inverts finite X(p) in the circumcircle of ABC using GeoGebra circle reflection. `B formula` stores one cyclic barycentric coordinate. The parser accepts explicit relations within the target X(n) entry, including `inverse-in-circumcircle of` and `circumcircle-inverse of`, equivalent-pair lists, wrapped intersections, symbolic `∩` intersections, and line lists that share a heading with curve incidences. Listed pairs may use braces, parentheses, or a dot typo between IDs; an isolated damaged numeric token is skipped. It reads up to ten eligible listed lines and proposes pairs of lines with disjoint endpoints. An explicit intersection is preferred over an incidence-only pair when its dependencies become available. Conditions and transformations relative to a triangle other than ABC are excluded.

Coordinate extraction accepts a direct first coordinate followed by `: :`, an exact cyclic `f(a,b,c) : f(b,c,a) : f(c,a,b), where f(a,b,c) = ...` pattern (also angle variables and function names g, h, or t), or three explicit coordinates whose normalized expressions agree under cyclic rotation. HTML superscripts, square brackets, wrapped formulas, implicit products such as `a2b4`, `aS`, and `rR`, arithmetic, constant powers, square roots including `Sqrt`, `π`/`Pi`, and named trigonometric functions are normalized into a checked expression. A cyclic header or formula may continue across several HTML lines. Ambiguous `π8` is rejected rather than read as `8π`; X(3371)'s formula is a reviewed seed. Angle variables mean angles of ABC; lower-case sides mean opposite side lengths. The supported Conway symbols are `S=2 area`, `SA/SB/SC=(b²+c²−a²)/2` and cycles, `s`, `sa/sb/sc`, `r`, and `R`. Other symbols and multi-line auxiliary-variable chains are deferred. Cyclic permutations generate the other two coordinates; a trilinear first coordinate is multiplied by `a` during import, so only `B` is stored or interpreted at runtime. A zero barycentric sum with a nonzero direction vector is classified as ideal and is not admitted through `B` yet; thirteen parsed formulas had this result on both samples.

`V` candidates require a finite source away from the circumcenter on both sample triangles. The generated graph currently selects 59 such inversions. Runtime coordinate formulas accept the same 500-character limit as the importer.

Run from the repository root with Python 3 and `beautifulsoup4`:

```sh
python scripts/geogebra/tools/triangle_center_import.py fetch --parts 1 2 3 4 5 37
python scripts/geogebra/tools/triangle_center_import.py native
python scripts/geogebra/tools/triangle_center_import.py build
python scripts/geogebra/tools/triangle_center_import.py check
python scripts/geogebra/tools/triangle_center_import.py verify
```

Before `native`, `build`, or `check`, run `/scripts/geogebra/browser/verification.html?page=center-anchors` against the local site, download its native coordinate sample, and copy it to `.cache/triangle-centers/native-atlas.json`. This ignored build-time sample covers two fixed triangle shapes and is never shipped to the app. Update the unavailable entries in `native-status.txt` from the same screen when the GeoGebra engine changes. The manually cached ETC Parts 1 and 2 feed `native`, which regenerates the direction entries in that same file from the target's own `(parallel)` or infinity-line incidence lists. This is an explicit maintenance action, not automatic ETC synchronization.

`fetch` is the manual page update step. `build` uses cached HTML and the build-time coordinate sample, writes compact chunks, and writes a local `selected.tsv` audit table with source sentences. `check` regenerates from the cache and compares with Git data. `verify` needs neither cached HTML nor the coordinate sample; it checks all chunk IDs, dependencies, directed cycles, formula syntax, ideal/finite input types, and exclusions. A candidate enters only when its dependencies are native or already constructible; forward numeric references are allowed. Selection first closes the relation-only graph, then forms weak components of the unresolved extended-center dependency graph; shared native and already closed points do not join components. Each component gets `min(6, max(1, ceil(size/5)))` coordinate-anchor slots by default, adjustable with `--max-coordinate-anchors-per-component`; previously selected IDs in `coordinate-priority.txt` remain eligible even when they exceed that local allowance. There is no global anchor cap. `seeds.txt` fixes the previously screened X(8004) line pair when several extracted pairs compete; seed dependencies still have to close without cycles and pass the numeric graph screen. Anchor selection favors unresolved dependents, with a small quota per page. All parsed formula variants must agree on both sample triangles; if the target has a known ETC line, its point must lie on at least one such line. After reopening the graph, simpler constructions replace formula anchors whenever possible. This batch retains 321 formula rows after selecting 355 candidate anchors. Isogonal/isotomic recipes bind their input point once before calling the shared conjugate builder, so a coordinate source does not get copied through every signed-area term. The full graph has maximum depth 6; the 7999 rows occupy 179,254 bytes before compression.

`native-status.txt` records 229 native IDs that GeoGebra returned as undefined on at least one of the acute and obtuse representative triangles. A bare ID means unavailable; an ID followed by two finite native IDs gives an ideal direction. Of the 229, 191 have a usable ideal direction from cached ETC Parts 1 and 2. X(1912) is marked ideal but its two available native lines disagree on the samples, so it remains excluded. The other 37 unavailable IDs are not assumed ideal. `deferred-centers.txt` excludes X(72904), whose currently closed dependencies yield no consistent line pair. X(72060), previously excluded because its barycentric sum is zero, now has an `I` direction recipe. The build-time numeric graph checks every selected finite point and ideal direction on both shapes. A direct `TriangleCenter(...,idealId)` returns an undefined GeoGebra point because the engine has no drawable point at infinity; its direction remains available to dependent finite recipes. The earlier 35-point real-engine smoke test remains available; this batch used rule tests and the numeric graph screen. These samples do not prove behavior on every special triangle.
