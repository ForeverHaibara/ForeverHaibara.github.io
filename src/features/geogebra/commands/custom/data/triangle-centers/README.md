# Triangle center recipe data

The ten `chunks/*.txt` files contain 6340 supported centers (2026-10-31). They are generated from 17 reviewed entries in `seeds.txt` and 6323 automatically extracted constructions from [ETC Parts 3](https://faculty.evansville.edu/ck6/encyclopedia/ETCPart3.html), [4](https://faculty.evansville.edu/ck6/encyclopedia/ETCPart4.html), [5](https://faculty.evansville.edu/ck6/encyclopedia/ETCPart5.html), and [37](https://faculty.evansville.edu/ck6/encyclopedia/ETCPart37.html). Git tracks the compact generated data and extraction rules. ETC pages are manually downloaded to `.cache/triangle-centers/`, which Git ignores; no runtime or scheduled synchronization occurs.

Each row is `id operation references...`. `M p q` means midpoint; `R p q` reflects X(p) in X(q); `C p` and `A p` are complement and anticomplement. `J p q r s` intersects two lines; `P p q r` projects X(p) onto line X(q)X(r); `L p q r` reflects X(p) across line X(q)X(r). `G p` and `T p` are isogonal and isotomic conjugates of X(p), using the same point builders as the public custom tools. The parser accepts explicit relations within the target X(n) entry, including equivalent-pair lists, wrapped intersections, symbolic `∩` intersections, and the standard "X(n) lies on these lines" lists. It reads up to ten eligible listed lines and proposes pairs of lines with disjoint endpoints. An explicit intersection is preferred over an incidence-only pair when its dependencies become available. Barycentric expressions are not parsed. Conditions and transformations relative to a triangle other than ABC are excluded.

Run from the repository root with Python 3 and `beautifulsoup4`:

```sh
python scripts/geogebra/tools/triangle_center_import.py fetch --parts 3 4 5 37
python scripts/geogebra/tools/triangle_center_import.py build
python scripts/geogebra/tools/triangle_center_import.py check
python scripts/geogebra/tools/triangle_center_import.py verify
```

Before `build` or `check`, run `/scripts/geogebra/browser/verification.html?page=center-anchors` against the local site, download its native coordinate sample, and copy it to `.cache/triangle-centers/native-atlas.json`. This ignored build-time sample covers two fixed triangle shapes and is never shipped to the app. Update `native-unavailable.txt` from the same screen when the GeoGebra engine changes.

`fetch` is the manual update step. `build` uses cached HTML and the build-time coordinate sample, writes compact chunks, and writes a local `selected.tsv` audit table with source sentences. `check` regenerates from the cache and compares with Git data. `verify` needs neither cached HTML nor the coordinate sample; it checks all chunk IDs, dependencies, directed cycles, and exclusions. A candidate enters only when its dependencies are native or already constructible; forward numeric references are allowed. Selection prefers affine constructions over line intersections and conjugates, caps each dependency path at one conjugation, and limits estimated expression growth. On both sample triangles, candidate lines must have nonzero lengths and an independent intersection; an incidence-only pair must also agree with a third independent listed line when available. Conjugates must be finite on both shapes. After graph closure, the builder revisits earlier intersections when a safer or explicitly stated definition has become available, then rechecks the final line pairs. The full graph has maximum depth 6; the 6340 rows occupy 117,993 bytes before compression.

`native-unavailable.txt` records 229 native IDs that GeoGebra returned as undefined on at least one of the acute and obtuse representative triangles. The screen checks all 3053 native IDs, so choosing another ETC relation cannot introduce an unscreened native dependency. `known-nonfinite.txt` excludes X(72060), whose barycentric sum is identically zero. The final 1746 distinct native references are outside the exclusion set; the build-time numeric graph is finite on both shapes, and 35 representative centers passed creation, obtuse-triangle, dragging, and export/reopen checks (`/scripts/geogebra/browser/verification.html?page=centers`). These samples do not prove behavior on every special triangle. See the [staged plan](../../docs/triangle-centers-plan.md).
